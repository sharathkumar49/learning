2. Anatomy of a Java Program:

2.1 Functions and Methods

Functions (called *methods* in Java) are the smallest building blocks of a Java program. Each method encapsulates a specific task—much like pressing a particular button on a TV remote triggers one action.

- Access Modifier: determines visibility (e.g., 'public', 'private')  
- Return Type: data type the method returns; use 'void' if nothing is returned  
- Method Name: descriptive identifier, follows camelCase  
- Parameters: inputs to the method (we’ll cover these later)  
- Braces: opening '{' goes on the same line as the method signature  

'''java
// A method that sends an email
void sendEmail() {
    // implementation goes here
}
'''



2.2 Classes as Containers

In Java, every method must belong to a class. A class groups related methods (and fields), helping you organize code like supermarket sections organize products.

- Keyword: 'class'  
- Class Name: follows PascalCase  
- Access Modifier: usually 'public' for top‐level classes  

'''java
// A simple class with one method
class Main {
    void main() {
        // code to execute
    }
}
'''



2.3 The 'main' Method: Entry Point

Every runnable Java application needs one 'main' method. When you launch your program, the Java Virtual Machine (JVM) looks for this method and starts executing its code.

'''java
public class Main {
    public void main() {
        // program starts here
    }
}
'''

- The class containing 'main' is often named 'Main'.  
- 'main' must be defined exactly once in your program.



2.4 Access Modifiers

| Modifier  | Visibility                              |
|-----------|-----------------------------------------|
| public    | Accessible from any other class         |
| private   | Accessible only within its own class    |
| (others)  | 'protected', package-private, etc.      |

Most examples in this course use 'public' for both classes and methods.



2.5 Naming Conventions

| Element | Convention   | Example                 |
|---------|--------------|-------------------------|
| Classes | PascalCase   | 'Main', 'EmailSender'   |
| Methods | camelCase    | 'sendEmail()', 'calculateTotal()' |

- PascalCase: capitalize the first letter of every word  
- camelCase: lowercase first word, capitalize subsequent words

|                                  |
+----------------------------------+
'''

- public class Main { … }

4. How Java Code Gets Executed:
When you click Run in IntelliJ (or invoke commands manually), two major phases happen under the hood:

1. Compilation – your '.java' source files are turned into Java bytecode ('.class' files).  
2. Execution – the Java Virtual Machine (JVM) loads those bytecode files and converts them into native machine code for your OS.



4.1 Compilation Step

1. Locate your source file  
   - In IntelliJ: right-click 'Main.java' → Open in Terminal (Windows: Open in Command Prompt).  
   - You’ll land in the folder that contains 'Main.java'.

2. Run the Java compiler  
   '''bash
   javac Main.java
   '''
   - On macOS/Linux, file names are case-sensitive: use 'Main.java', not 'main.java'.  
   - This produces 'Main.class' in the same directory.

3. Verify the '.class' file  
   | macOS/Linux      | Windows        |
   |------------------|----------------|
   | 'ls'             | 'dir'          |
   | Output:          | Output:        |
   | 'Main.class'     | 'Main.class'   |

4. IntelliJ’s build output  
   - IntelliJ compiles into the 'out/' folder by default.  
   - Project panel view:

     '''
     hello-world/
     ├── src/
     │   └── com/
     │       └── codewithmosh/
     │           └── Main.java
     └── out/
         └── production/
             └── hello-world/
                 └── com/
                     └── codewithmosh/
                         └── Main.class
     '''




4.2 Java Bytecode: Platform Independence

- Bytecode ('.class') is a platform-neutral, intermediate form.  
- Any OS with a JRE can run it—Windows, macOS, Linux, etc.  
- You can download a JRE from [java.com/download](https://java.com/download).




4.3 Execution Step

1. Invoke the JVM  
   '''bash
   # From the directory containing 'com'
   java com.codewithmosh.Main
   '''
   - 'java': starts the JVM.  
   - 'com.codewithmosh.Main': fully qualified class name (matches 'package' + class).  
   - JVM locates 'com/codewithmosh/Main.class', loads the bytecode, and JIT-compiles it to native code.

2. See your program run  
   '''
   hello world
   '''



4.4 Under-the-Hood Architecture

'''
   [ Main.java (source) ]
             |
          javac
             |
   [ Main.class (bytecode) ]
             |
           JVM
             |
   [ Native Machine Code ]
             |
     Program Executes on OS
'''

- JDK’s 'javac' turns '.java' → '.class'.  
- JRE’s JVM turns '.class' → OS-specific instructions.




4.5 Why This Matters

- Portability: write once, run anywhere.  
- Separation of concerns: compile-time checks vs. runtime execution.  
- Visibility: IntelliJ hides these steps, but knowing them helps troubleshoot build/run issues.



Tip: Experiment on the command line to reinforce what IntelliJ does for you automatically.

2. Variables: 



2. Variables

2.1 What Are Variables?

A variable is a named “box” in your computer’s memory where you can store a piece of data temporarily. Think of it like a labeled locker in a hallway:

'''
+---------+      +---------+      +---------+
|  age    | ---> |   30    |      |   …     |
+---------+      +---------+      +---------+
| temp    | ---> |   20    |      |   …     |
+---------+      +---------+      +---------+
'''

Each locker has:
- A label (the variable name)  
- A type (what kind of items it can hold)  
- A value (what’s inside right now)




2.2 Declaring & Initializing:

To create a variable, you declare its type, give it a name (identifier), and then assign an initial value:

'''java
int age = 30;
'''

- int: the variable’s type (only whole numbers)  
- age: identifier—how you refer to this locker  
- =: assignment operator—places the value into the locker  
- 30: initial value (initialization)  

Key point: you must initialize a variable before reading it.




2.3 Reading & Updating:

Once initialized, you can read and change the value:

'''java
age = 35;                  // update the value
System.out.println(age);   // prints 35
'''

- Changing a variable overwrites the old contents of its memory box.  
- Printing a variable displays its current value instead of literal text.




2.4 Multiple Declarations (Not Recommended)

Java lets you declare more than one variable on the same line:

'''java
int age = 30, temperature = 20;  // legal but hard to read
'''

Better practice: one declaration per line for clarity:

'''java
int age = 30;
int temperature = 20;
'''



2.5 Copying Between Variables

You can assign one variable’s value to another, effectively cloning the contents of one locker into another:

'''java
int myAge = 30;
int herAge = myAge;      // herAge now holds 30
System.out.println(herAge);  // prints 30
'''

- The second variable ('herAge') gets its own memory box with a copy of the value stored in 'myAge'.




2.6 Naming Conventions

Follow camelCase for variable names to keep code consistent and readable:

- Start with a lowercase letter  
- Capitalize the first letter of each subsequent word  

Examples:
- 'myAge'  
- 'userScore'  
- 'totalPrice'



Visual Recap

'''
Declare & Initialize:
  int age = 30;

Memory Snapshot:
  age ──▶ 30

Update:
  age = 35

Memory Snapshot:
  age ──▶ 35

Copy:
  int herAge = age
  herAge ──▶ 35
'''

3. Primitive Types: 

3.1 Categories of Types

In Java, every variable has a type. Types fall into two broad categories:

- Primitive types, which store simple values directly in memory  
- Reference types, which store references (addresses) to objects  

This section covers the eight built-in primitive types.



3.2 The Eight Primitive Types

| Type     | Size    | Range / Values                                                       | Common Use Case                         |
|----------|---------|-----------------------------------------------------------------------|-----------------------------------------|
| byte     | 1 byte  | –128 to 127                                                           | Very small whole numbers                |
| short    | 2 bytes | –32,768 to 32,767                                                     | Medium-range whole numbers              |
| int      | 4 bytes | –2,147,483,648 to 2,147,483,647                                       | Default for whole numbers               |
| long     | 8 bytes | –9,223,372,036,854,775,808 to 9,223,372,036,854,775,807               | Very large whole numbers                |
| float    | 4 bytes | Approximately 1.4 × 10⁻⁴⁵ to 3.4 × 10³⁸ (single precision)              | Decimal numbers when memory is tight    |
| double   | 8 bytes | Approximately 4.9 × 10⁻³²⁴ to 1.7 × 10³⁰⁸ (double precision)             | Default for decimal numbers             |
| char     | 2 bytes | Unicode code unit from '\u0000' (0) to '\uFFFF' (65,535)               | Single Unicode character                |
| boolean  | 1 bit*  | 'true' or 'false'                                                     | Logical values                          |

*Actual storage of boolean is JVM-dependent and may use a full byte or more.




3.3 Choosing the Right Primitive

Choosing the smallest type that comfortably fits your data conserves memory and communicates intent.

3.3.1 Storing Age

'''java
byte age = 30;
'''

Memory snapshot:
'''
age ──▶ [  30  ]  (1 byte)
'''

3.3.2 Counting Views

Use 'int' for counts up to ~2.1 billion. Underscores separate groups of digits for readability (since Java 7):

'''java
int viewsCount = 1_234_567_890;
'''

When the value exceeds 'int' range, switch to 'long' and add an 'L' suffix:

'''java
long viewsCount = 3_000_000_000L;
'''

Using uppercase 'L' avoids confusion with the digit '1'.




3.4 Decimal Numbers

Floating-point literals default to 'double'. To store in a 'float', add an 'F' suffix:

'''java
double priceDouble = 10.99;    // OK
float  priceFloat  = 10.99F;   // OK
// float priceFloat = 10.99;   // Error: found double, required float
'''




3.5 Characters & Booleans

- char holds a single character. Use single quotes:
  '''java
  char letter = 'A';
  '''
- boolean holds a true/false value:
  '''java
  boolean isEligible = false;
  '''

Remember: single quotes for 'char', double quotes for 'String'.




3.6 Reserved Keywords

Java reserves words (like 'public', 'class', 'static', 'int') for its own syntax. You cannot use these as variable, method, or class names.




3.7 Complete Example

'''java
package com.codewithmosh;

public class Main {
    public static void main(String[] args) {
        byte    age         = 30;
        long    viewsCount  = 3_123_456_789L;
        float   price       = 10.99F;
        char    letter      = 'A';
        boolean isEligible  = false;
    }
}
'''




3.8 Visual Recap

'''
age (byte)         ──▶ [ 30 ]
viewsCount (long)  ──▶ [ 3_123_456_789 ]
price (float)      ──▶ [ 10.99 ]
letter (char)      ──▶ [ 'A' ]
isEligible (bool)  ──▶ [ false ]
'''




3.9 Key Takeaways

- Use the smallest primitive type that fits your data.  
- Numeric literals default to 'int'/'double'; suffix with 'L' or 'F' for 'long' and 'float'.  
- Use underscores in large numeric literals to improve readability.  
- Single quotes for 'char', double quotes for 'String'.  
- Never use Java’s reserved keywords as identifiers.

4. Reference Types:



4. Reference Types:

4.1 Primitive vs. Reference Types

- Primitive types (e.g., 'int', 'byte', 'boolean') store simple values directly in memory.  
- Reference types store references (addresses) to complex objects created on the heap.  
- Every built-in type beyond the eight primitives is a reference type (classes, arrays, interfaces).




4.2 Importing Classes & Packages

When you use a class from another package, you must import it:

'''java
import java.util.Date;    // Brings java.util.Date into scope

package com.codewithmosh;  // Your project’s base package
'''

- Packages provide namespaces, allowing classes with the same name (e.g., 'Date') to coexist in different packages ('java.util.Date' vs. 'java.sql.Date').




4.3 Declaring & Initializing Reference Variables

Syntax differs from primitives:

'''java
Date now = new Date();
'''

Breakdown:

1. Type: 'Date' (a class)  
2. Variable name: 'now' (identifier)  
3. 'new' operator: allocates memory for the object on the heap  
4. Constructor call: 'new Date()' invokes the 'Date' class’s constructor  
5. Assignment: reference to the newly created object is stored in 'now'




4.4 Memory Layout

'''
Stack Frame (main):
  ├─ age (byte)  ──▶ [30]            // primitive value stored directly
  └─ now (ref.) ──▶ Object @0xABC   // reference to heap object

Heap:
  Object @0xABC: Date instance data...
'''

- Primitive: value lives in the variable’s memory slot.  
- Reference: variable holds a pointer to an object on the heap.  

Java’s garbage collector automatically frees unreachable objects; you don’t manually release memory.




4.5 Classes, Objects & Instances

- Class: blueprint or template (e.g., 'Date', 'Human').  
- Object (instance): concrete realization of a class (e.g., 'new Date()', 'new Human()').  
- You can have multiple instances (objects) from one class:
  '''java
  Human john = new Human();
  Human mary = new Human();
  '''




4.6 Accessing Members with the Dot Operator

Reference variables expose fields and methods:
'''java
now.getTime();           // calls Date’s getTime() method
System.out.println(now); // uses PrintStream.println(Object)
'''

- Primitives have no members: 'age.' offers no suggestions.

5. Primitive vs Reference Types: 


5. Primitive vs Reference Types:

5.1 Recap of Type Categories

- Primitive types store simple values directly in their own memory slots.  
- Reference types store pointers (references) to objects allocated on the heap.  
- This distinction affects how variables are copied and how updates propagate.



5.2 Primitive Assignment and Independence

'''java
package com.codewithmosh;

public class Main {
    public static void main(String[] args) {
        byte x = 1;      // Declare primitive x and assign 1
        byte y = x;      // Copy the value of x into y
        x = 2;           // Reassign x to 2
        System.out.println(y);  // Prints 1
    }
}
'''

When you assign one primitive to another, you copy the raw value. After copying:

- x and y occupy separate memory locations.  
- Changing x does not affect y.

---

 Memory Layout (Primitives)

'''
Stack frame for main():
  ├─ x: [1]      // before x = 2
  └─ y: [1]

After x = 2:
  ├─ x: [2]
  └─ y: [1]
'''




5.3 Reference Assignment and Sharing

'''java
package com.codewithmosh;

import java.awt.Point;

public class Main {
    public static void main(String[] args) {
        Point point1 = new Point(1, 1);  // Allocate a Point object at heap address 0x100
        Point point2 = point1;           // Copy the reference value

        point1.x = 2;                    // Mutate the object via point1
        System.out.println(point2);      // Prints java.awt.Point[x=2,y=1]
    }
}
'''

Key differences:

- point1 holds the address of the newly created 'Point' object.  
- point2 receives the same address—both refer to the *same* object.  
- Mutating via one reference is visible through the other.




Memory Layout (References)

'''
Stack frame for main():
  ├─ point1: 0x100 ─▶ Heap@0x100: Point { x=1, y=1 }
  └─ point2: 0x100 ─┘

After point1.x = 2:
Heap@0x100: Point { x=2, y=1 }
'''




5.4 Step-by-Step Execution

1. Line 1 ('new Point(1,1)'):  
   - Heap allocates space at e.g. 0x100.  
   - Stores internal fields 'x=1', 'y=1'.  
   - Returns reference 0x100.

2. Line 2 ('point2 = point1'):  
   - Copies the value 0x100 from 'point1' into 'point2'.  
   - Both variables now refer to the same object.

3. Line 3 ('point1.x = 2'):  
   - Follows reference 0x100, writes 'x=2' into the object’s field.  

4. Line 4 ('System.out.println(point2)'):  
   - Calls 'point2.toString()', showing updated coordinates.




5.5 Why “Reference” Types?

- Variables of reference types do *not* store object data directly.  
- They store an address (reference) pointing to the object in memory.  
- Copying a reference variable duplicates the pointer, not the object.




5.6 Practical Implications

- To get an independent copy of an object, use a copy constructor or 'clone()'.  
- Be cautious when passing reference types into methods—mutations inside the method affect the caller’s object.  
- Immutable reference types (e.g., 'String') avoid shared-mutation pitfalls.




5.7 Key Takeaways

- Primitive assignments copy values; reference assignments copy addresses.  
- Primitives are independent after assignment; references share the same object.  
- Mutations on shared objects are seen by all references.  
- Use object-copy strategies to prevent unintended side effects.

6. Strings: 

6.1 What Is a String?

A string literal like '"Hello World"' is a sequence of characters in double quotes. In Java, any literal text between quotes is a 'String' value.




6.2 Declaring String Variables

'''java
package com.codewithmosh;

public class Main {
    public static void main(String[] args) {
        // Using the String literal shorthand
        String message = "Hello World";
        System.out.println(message);
    }
}
'''

- 'String' is a reference type defined in 'java.lang'.  
- The 'java.lang' package is automatically imported, so no 'import' statement is needed.  
- You can also write 'new String("Hello World")', but most of the time this is redundant.




6.3 String Immutability & Memory

Strings are immutable: once created, you cannot change their contents. Any “modification” returns a new 'String' object.

 Memory Diagram

'''
String Pool (JVM)             Heap
────────────────            ─────────────────
"Hello World"   <───┐         (other objects)
                    │
Stack Frame         │
────────────────    │
message ────────────┘
'''

- String pool holds unique literal instances.  
- 'message' references the pooled '"Hello World"'.  
- Methods like 'replace()' allocate a brand-new 'String' elsewhere.




6.4 Concatenation

Join strings (or strings + primitives) using '+':  

'''java
String excited = message + "!!";
System.out.println(excited);  // Hello World!!
'''




6.5 Common String Methods

All 'String' methods are accessed with the dot operator ('.'). Each returns either a value or a brand-new 'String'.

| Method                         | Purpose                                                | Example                              | Result        |
| ------------------------------ | ------------------------------------------------------ | ------------------------------------ | ------------- |
| 'endsWith(String suffix)'      | Checks if string ends with given suffix                | 'message.endsWith("!!")'             | 'false'       |

> Note on parameters vs. arguments:

'''

- 'message.replace("!", "*")' does not alter 'message'.  
- It returns a new 'String' ('starred') with replacements applied.




6.7 When to Use Which Method

- Validation: 'length()', 'startsWith()', 'endsWith()'  
- Search: 'indexOf()'  
- Transformation: 'replace()', 'toLowerCase()', 'toUpperCase()', 'trim()'  
- Concatenation: '+' operator or 'StringBuilder' for many pieces

7. Escape Sequences:

7.1 Why Escape Sequences Are Needed

When you include certain special characters directly in a string literal, the compiler misinterprets them as part of the syntax rather than as data. Escape sequences let you embed these special characters by prefixing them with a backslash ('\').



7.2 Escaping Double Quotes ('"')

Problem:
'''java
String msg = "Hello "Mosh"";  
// Compilation error: unclosed string literal
'''

The compiler thinks the second '"' ends the string, so it doesn’t recognize the rest.


Solution:

Prefix each internal double quote with a backslash ('\"'):

'''java
String msg = "Hello \"Mosh\"";
System.out.println(msg);  // Prints: Hello "Mosh"
'''



7.3 Escaping Backslashes ('\')

Windows Path Example:

To represent a Windows path like 'C:\Windows\System32', each backslash in code must be escaped ('\\'):

'''java
String path = "C:\\Windows\\System32";
System.out.println(path);  // Prints: C:\Windows\System32
'''

- In code: '\\'  
- In output: '\'




7.4 New Line ('\n')

Insert a line break at the escape sequence:

'''java
String multiLine = "First Line\nSecond Line";
System.out.println(multiLine);
'''

Output:
'''
First Line
Second Line
'''

- '\n' tells Java to start a new line at that point.




7.5 Tab ('\t')

Insert a horizontal tab to align or indent text:

'''java
String tabbed = "Column1\tColumn2\tColumn3";
System.out.println(tabbed);
'''

Output (one tab between columns):
'''
Column1    Column2    Column3
'''

- '\t' adds a tab character (typically 4–8 spaces in console).




7.6 Common Escape Sequences:

| Sequence | Meaning                     | Example Literal        | Printed Output                      |
|----------|-----------------------------|------------------------|-------------------------------------|
| '\"'     | Double quote                | '"She said, \"Hi\""'   | She said, "Hi"                      |
| '\\'     | Backslash                   | '"C:\\Temp\\file.txt"' | C:\Temp\file.txt                    |
| '\n'     | New line (line break)       | '"A\nB"'               | A  
B                                   |
| '\t'     | Horizontal tab              | '"A\tB"'               | A    B                              |

> Note: Java supports additional escapes ('\r', '\b', '\f', '\''), but they are used less frequently.



7.7 Visualizing Escape Mechanics:

'''
Code                 →  String Literal  →  Runtime String
----------------------------------------------------------------
"Hello \"Mosh\""     →  Hello "Mosh"    →  Hello "Mosh"
"C:\\Windows\\"      →  C:\Windows\     →  C:\Windows\
"Line1\nLine2"       →  Line1\nLine2    →  Line1
                                       Line2
'''

Each '\' in source code signals that the next character is part of the data, not the syntax.



With these four escape sequences—'\"', '\\', '\n', and '\t'—you can safely embed quotes, backslashes, new lines, and tabs in your Java strings.

8. Arrays: 

8.1 What Are Arrays:

Arrays store a fixed-size sequence of elements of the same type, such as numbers, strings, or objects.  

They provide indexed access, letting you read or write each item using its position, starting at zero.  

Use arrays when you know the number of elements up front or don’t need to change the size at runtime.  




8.2 Declaring and Creating an Array:

To declare an array, append square brackets ('[]') to the type.  

To allocate memory, use the 'new' operator with the desired length:

'''java
int[] numbers = new int[5];
'''

This creates an 'int' array with room for five elements, all initialized to their default values.  




8.3 Accessing and Modifying Elements:

Each element is accessed by its zero-based index:

'''java
numbers[0] = 1;
numbers[1] = 2;
'''

Reading an element:

'''java
int first = numbers[0];
'''

Using an invalid index (e.g., 'numbers[10]') throws an 'ArrayIndexOutOfBoundsException' at runtime.  




8.4 Arrays in Memory (Diagram):

Below is an ASCII diagram of 'int[] numbers = new int[5];' after assigning two values:

'''
numbers ──> +------+------+------+------+------+
             | [0]  | [1]  | [2]  | [3]  | [4]  |
             +------+------+------+------+------+
             |  1   |  2   |  0   |  0   |  0   |
             +------+------+------+------+------+
'''

Indexes run from 0 to length−1. Unassigned 'int' elements default to 0.  




8.5 Default Values by Type:

| Element Type                               | Default Value |
|--------------------------------------------|---------------|
| byte, short, int, long, float, double      | 0 or 0.0      |
| char                                       | '\u0000'      |
| boolean                                    | false         |
| reference types (e.g., String, Object)     | null          |




8.6 Printing Arrays:

Printing an array reference directly shows its class name and hash code, not the contents:

'''java
System.out.println(numbers);
// e.g., [I@1a2b3c4d
'''

Use 'Arrays.toString(...)' for a readable representation:

'''java
import java.util.Arrays;

System.out.println(Arrays.toString(numbers));
// Outputs: [1, 2, 0, 0, 0]
'''



8.7 Array Initialization Shortcut:

If you know the elements at declaration, use brace-enclosed lists:

'''java
int[] numbers = {2, 3, 5, 1, 4};
'''

This creates an 'int' array of length 5 containing those values.  




8.8 Array Length:

Every array has a 'length' field you can read:

'''java
int size = numbers.length;
System.out.println(size);  // Prints: 5
'''

Arrays cannot change size after creation. For dynamic resizing, use collection classes such as 'ArrayList'.  




8.9 Sorting an Array:

To sort a primitive or object array in-place, call 'Arrays.sort(...)':

'''java
import java.util.Arrays;

Arrays.sort(numbers);
System.out.println(Arrays.toString(numbers));
// Outputs: [1, 2, 3, 4, 5]
'''



8.10 Key Takeaways:

- Arrays have fixed length and homogeneous element types  
- Use zero-based indexing to access elements  
- Default values depend on element type (numeric → 0, boolean → false, references → null)  
- 'Arrays.toString' and 'Arrays.sort' from 'java.util.Arrays' simplify printing and sorting  
- For variable-sized collections, prefer classes in the Java Collections Framework

9. Multi-dimensional Arrays: 

9.1 What Are Multi-dimensional Arrays

Arrays of arrays let you model grids, tables, or higher-dimensional data.  
A two-dimensional array is a matrix (rows × columns).  
A three-dimensional array extends this to a “cube” of data (depth × rows × columns).  
They’re common in scientific computations, graphics, and game development.




9.2 Declaring a Two-Dimensional Array

To declare a 2D 'int' array:

'''java
int[][] numbers = new int[2][3];
'''

- The first '[]' is for rows (2)  
- The second '[]' is for columns (3)  
- All elements default to '0' (for 'int')

If you write only one '[]' on one side, you’ll get a compilation error—each dimension needs its bracket pair.




9.3 Accessing and Modifying Elements

Use two zero-based indexes: 'numbers[row][column]'.

'''java
numbers[0][0] = 1;    // First row, first column
numbers[1][2] = 6;    // Second row, third column
'''

Using an out-of-bounds index (e.g., 'numbers[2][0]') throws 'ArrayIndexOutOfBoundsException' at runtime.




9.4 Visualizing a 2×3 Matrix

'''
numbers ──> +------+------+------+
             | [0][0] | [0][1] | [0][2] |   ← Row 0
             +------+------+------+
             | [1][0] | [1][1] | [1][2] |   ← Row 1
             +------+------+------+
             |   1    |   0    |   0    |
             +------+------+------+
             |   0    |   0    |   6    |
             +------+------+------+
'''




9.5 Printing Multi-dimensional Arrays

Printing directly still shows a memory address:

'''java
System.out.println(numbers);
// e.g., [[I@7e0b241
'''

Use 'Arrays.deepToString(...)' to see all elements:

'''java
import java.util.Arrays;

System.out.println(Arrays.deepToString(numbers));
// Outputs: [[1, 0, 0], [0, 0, 6]]
'''




9.6 Initializing with Literals

If you know the values in advance, use brace-enclosed lists:

'''java
int[][] numbers = {
    {1, 2, 3},   // Row 0
    {4, 5, 6}    // Row 1
};
System.out.println(Arrays.deepToString(numbers));
// Outputs: [[1, 2, 3], [4, 5, 6]]
'''

Each inner '{…}' defines one row, itself an array.




9.7 Three-Dimensional Arrays

Add another '[]' and length for the third dimension:

'''java
int[][][] cube = new int[2][3][4];
// 2 blocks, each with 3 rows and 4 columns
'''

Access with three indexes: 'cube[block][row][column]'.




9.8 Key Points

- Each dimension requires its own '[]' in the declaration.  
- Multi-dimensional arrays default all values to the type’s default ('0', 'false', or 'null').  
- Use 'Arrays.deepToString' to print nested arrays.  
- Use brace syntax '{ {...}, {...} }' for literal initialization.  
- For dimensions beyond three or variable sizes, consider specialized libraries or collections.

10. Constants: 

10.1 Why Use Constants

- Variables in Java can be reassigned any time after initialization.  
- Certain values—like π, configuration flags, or fixed rates—should remain unchanged once set.  
- Declaring such values as constants prevents accidental reassignment, enforces intent, and improves code safety.




10.2 Declaring a Constant with 'final'

Use the 'final' modifier before the type to mark a variable as immutable:

'''java
final float PI = 3.14F;
'''

- 'final' ensures the variable cannot be reassigned after its initial value.  
- The 'F' suffix tells the compiler to treat '3.14' as a 'float' (otherwise it defaults to 'double').




10.3 Reassignment Causes a Compilation Error

Once initialized, any assignment to a 'final' variable triggers a compile-time error:

'''java
PI = 1.0F;  
// Error: cannot assign a value to final variable PI
'''

Flow of events:

'''
+-----------------------+
|   Declare PI as final |
+-----------------------+
            ↓
+-----------------------+
|   PI = 3.14F          |
+-----------------------+
            ↓
+-----------------------+
| Attempt PI = 1.0F     |
+-----------------------+
| Compilation error     |
+-----------------------+
'''




10.4 Naming Conventions

| Category         | Naming Style      | Example     |
|------------------|-------------------|-------------|
| Regular Variable | lowerCamelCase    | radius      |
| Constant         | UPPER_SNAKE_CASE  | PI, MAX_SIZE|

- By convention, constants use all uppercase letters and underscores.  
- This visual distinction signals immutability to anyone reading the code.




10.5 Best Practices

- Group related constants in one class or interface (e.g., 'MathConstants', 'Config').  
- Prefer 'enum' when representing a fixed set of related constants (days of week, status codes).  
- Document each constant with a brief comment explaining its purpose.




10.6 Anecdote: Pronouncing π as “P”

    }

'''




10.8 Key Takeaways

- Use 'final' to create constants whose value cannot change.  
- Include the correct literal suffix ('F' for 'float', 'L' for 'long', etc.).  
- Follow naming conventions: constants in uppercase with underscores.  
- Leverage grouping and 'enum' for better organization and readability.

11. Arithmetic Expressions: 

11.1 Expressions, Operators & Operands

- Expression: any code fragment that produces a value  
- Operator: symbol denoting an operation ('+', '-', '*', '/', '%', '++', '--', '+=', etc.)  
- Operand: the values or variables the operator works on  

Example:
'''java
int result = 10 + 3;
'''
- Operator: '+'  
- Operands: '10', '3'  
- Expression '10 + 3' produces '13'




11.2 Core Arithmetic Operators

| Operator | Meaning            | Example            | Result          |
|----------|--------------------|--------------------|-----------------|
| '+'      | Addition           | '4 + 5'            | '9'             |
| '-'      | Subtraction        | '9 - 2'            | '7'             |
| '*'      | Multiplication     | '3 * 7'            | '21'            |
| '/'      | Division           | '10 / 3'           | '3' (integer)   |
| '%'      | Modulus (remainder)| '10 % 3'           | '1'             |




11.3 Integer vs. Floating-Point Division

# Integer Division
- When both operands are integer types, Java performs integer division, discarding any fractional part.
-  
  '''java
  int a = 10, b = 3;
  int div = a / b;       // div == 3
  int rem = a % b;       // rem == 1
  '''

# Floating-Point Division
- To preserve decimals, at least one operand must be 'float' or 'double'.
- Use literal suffixes ('F' for 'float', default is 'double') or cast:

  '''java
  double d1 = (double) 10 / 3;   // 3.3333333333333335
  double d2 = 10.0 / 3;          // 3.3333333333333335
  float  f  = 10F / 3;           // 3.3333333
  '''

Memory Preview (Integer Division)  
'''
10 ──► / ──► 3 ──► 3
10 ──► % ──► 3 ──► 1
'''




11.4 Type Promotion Rules

- Smaller integer types ('byte', 'short', 'char') are promoted to 'int' before arithmetic.  
- If one operand is 'long', result is 'long'; if one is 'float' or 'double', result is 'float'/'double'.  
- Casting back to a smaller type may lose data.




11.5 Increment ('++') and Decrement ('--')

- Postfix ('x++'): use the current value, then increment  
- Prefix ('++x'): increment first, then use the new value  

'''java
int x = 1;
int y = x++;    // y = 1, then x becomes 2

int a = 1;
int b = ++a;    // a becomes 2, then b = 2
'''

Execution Steps (Postfix)  
1. Evaluate 'x++' as old value ('1')  
2. Assign that to 'y'  
3. Increment 'x' to '2'  

Execution Steps (Prefix)  
1. Increment 'a' from '1' to '2'  
2. Evaluate '++a' as '2'  
3. Assign that to 'b'




11.6 Compound Assignment Operators

Combine an arithmetic operation with assignment in one succinct syntax:

| Shorthand | Equivalent To       |
|-----------|---------------------|
| 'x += 5'  | 'x = x + 5'         |
| 'x -= 5'  | 'x = x - 5'         |
| 'x *= 5'  | 'x = x * 5'         |
| 'x /= 5'  | 'x = x / 5'         |
| 'x %= 5'  | 'x = x % 5'         |

'''java
int x = 1;
x += 2;       // x is now 3
x *= 4;       // x is now 12
'''




11.7 Putting It All Together

'''java
public class Main {
    public static void main(String[] args) {
        int sum       = 10 + 3;               // 13
        int difference= sum - 5;              // 8
        int product   = difference * 2;       // 16

        int remainder = product % 5;          // 1

        System.out.println("precise = " + precise);
        System.out.println("x, y, z = " + x + ", " + y + ", " + z);
    }

'''

- Readability: avoid mixing prefix/postfix in complex expressions; split steps if necessary.  
- Use parentheses to enforce the desired order when combining several operators.

12. Order of Operations: 
Java follows the same precedence rules as standard arithmetic. Understanding these rules prevents unexpected results in your calculations.



12.1 Precedence Rules

1. Parentheses '()'  
2. Multiplication '*' and Division '/'  
3. Addition '+' and Subtraction '-'  

Operators on the same line are evaluated left to right.




12.2 Example Without Parentheses

'''java
public class Main {
    public static void main(String[] args) {
        int x = 10 + 3 * 2;  // ?
        System.out.println(x);
    }
}
'''

# Step-by-Step Evaluation

1. Identify sub-expression with highest precedence:  
   - '3 * 2' → '6'  
2. Rewrite the expression:  
   '''
   10 + 6
   '''
3. Compute addition:  
   '''
   10 + 6 → 16
   '''
4. Final result printed:  
   '''
   16
   '''




12.3 Using Parentheses to Alter Order

Wrap any sub-expression in '()' to force it to evaluate first:

'''java
public class Main {
    public static void main(String[] args) {
        int x = (10 + 3) * 2;  // ?
        System.out.println(x);
    }
}
'''

# Step-by-Step Evaluation

1. Evaluate parentheses first:  
   '''
   (10 + 3) → 13
   '''
2. Multiply the result by 2:  
   '''
   13 * 2 → 26
   '''
3. Printed output:  
   '''
   26
   '''




12.4 Precedence Chart

| Precedence Level | Operators        | Description                      |
|------------------|------------------|----------------------------------|
| 1 (highest)      | '()'             | Grouping                        |
| 2                | '*'  '/'         | Multiplication, Division         |
| 3 (lowest)       | '+'  '-'         | Addition, Subtraction            |




12.5 Visualizing with an Evaluation Tree

Expression: '10 + 3 * 2'

'''
         [+]
        /   \
      10     [*]
            /   \
           3     2
'''

1. Compute the '[*]' node → '6'.  
2. Compute the '[+]' node → '16'.

With parentheses: '(10 + 3) * 2'

'''
         [*]
        /   \
      [+]    2
      / \
    10   3
'''

1. Compute the '[+]' node → '13'.  
2. Compute the '[*]' node → '26'.




12.6 Tips & Common Pitfalls

- Always use parentheses to make complex expressions clear, even if precedence would handle it correctly.  
- Relying solely on precedence rules can lead to maintenance bugs when others read your code.  
- In mixed-type expressions, type promotion still follows the same precedence—cast or rewrite to avoid surprises.  
- When chaining many operators, break the expression into intermediate variables for readability.



By mastering operator precedence and judicious use of parentheses, you’ll write arithmetic expressions that behave exactly as you intend.

13. Casting (Type Conversion):

Java must reconcile different data types in expressions.  
Casting (type conversion) lets you convert a value from one type to another—automatically when safe, or manually when there’s potential data loss.


13.1 Why Casting?  
- Mixed‐type arithmetic (e.g., 'short + int', 'double + int') needs a common type.  
- Java either widens a smaller type to a larger one (implicit) or requires you to narrow manually (explicit).  
- Think of containers of different sizes: pouring small into large is safe; pouring large into small risks overflow or truncation.




13.2 Implicit Casting (Widening Conversion)  
Automatic, lossless conversion from a smaller to a larger type.

1. byte → short → int → long → float → double  
2. char → int → long → float → double  

Example: short + int  
'''java
short x = 1;       // occupies 2 bytes
int y = x + 2;     // x is widened to int behind the scenes
System.out.println(y);  // 3
'''

Under the hood  
'''
[short x: 1]            [literal 2: int]
      │                         │
      └─–─> widen to int (temp) ──┐
                                  ↓
                          compute int sum (3)
                                  ↓
                               assign to y
'''

Example: double + int  
'''java
double x = 1.1;    
double y = x + 2;   // 2 → 2.0 (double) automatically
System.out.println(y);  // 3.1
'''

Rule of Thumb  
- Java widens automatically when there’s no risk of losing information.




13.3 Explicit Casting (Narrowing Conversion)  
Manual conversion when moving to a smaller or less precise type—potentially loses data.

'''java
double x = 1.9;        
int y = (int) x + 2;   // (int)1.9 → 1 (truncation), then +2 → 3  
System.out.println(y); // 3
'''

- Syntax: '(TargetType) expression'  
- Behavior:  
  - Floating→integer: drops fractional part (no rounding)  
  - Larger integer→smaller integer: may overflow  




13.4 Numeric Promotion Rules  
Before most arithmetic:
- 'byte', 'short', 'char' → promoted to 'int'
- If one operand is 'long' → both become 'long'
- If one is 'float' → both become 'float'
- If one is 'double' → both become 'double'

This is why 'short + short' yields an 'int'.




13.5 Casting Incompatible Types: Parsing Strings  
You cannot cast 'String' → numeric type directly. Instead, use wrapper‐class parsers:

| Primitive | Wrapper Class      | Parse Method                   |
|-----------|--------------------|--------------------------------|
| 'int'     | 'java.lang.Integer'| 'Integer.parseInt("123")'      |
| 'short'   | 'java.lang.Short'  | 'Short.parseShort("123")'      |
| 'long'    | 'java.lang.Long'   | 'Long.parseLong("123")'        |
| 'float'   | 'java.lang.Float'  | 'Float.parseFloat("1.23")'     |
| 'double'  | 'java.lang.Double' | 'Double.parseDouble("1.23")'   |

'''java
String s = "42";
int n = Integer.parseInt(s) + 2;  // 44

String t = "3.14";
double d = Double.parseDouble(t) + 2;  // 5.14
'''

- Invalid formats (e.g., '"1.1"' for 'parseInt') throw 'NumberFormatException'.  
- Always trim and validate user input before parsing.




13.6 Visual Summary

'''
Widening Chain (implicit, safe):
byte → short → int → long → float → double

Narrowing (explicit, possible data loss):
double → float → long → int → short → byte

String parsing (conversion):
"123" ─> Integer.parseInt("123") ─> 123 (int)
'''

### Memory Diagram: 'short x = 1; int y = x + 2;'
'''
Stack:
  x (short) ──▶ [ 1 ]
   temp int ──▶ [ 1 ]  // implicit widening
           +        ──▶ result [ 3 ]
  y (int)   ──▶ [ 3 ]
'''



13.7 Best Practices & Pitfalls  
- Minimize explicit casts—they can hide data loss and lead to bugs.  
- Use correct suffixes ('F', 'L') for literals when right‐hand side type differs.  
- Parse user input safely: catch 'NumberFormatException', provide feedback.  
- For rounding instead of truncation, use methods from 'Math' (e.g., 'Math.round').  
- Consider 'BigDecimal' for monetary calculations needing high precision.



Mastering casting ensures your calculations and data transformations behave predictably, keeping both code safety and clarity in check.

14. The Math Class:
Java’s 'Math' class (in 'java.lang') provides a suite of static methods for common mathematical operations. You don’t need to import it—just call methods like 'Math.round()' or 'Math.random()' directly.




14.1 Method Overloading in 'Math'

Many 'Math' methods are overloaded: the same name supports different parameter types.

| Method      | Signatures                             | Return Type   | Purpose                                      |
|-------------|----------------------------------------|---------------|----------------------------------------------|
| 'round'     | 'round(float)' → 'int'                 | 'int'         | Rounds a 'float' to nearest whole number     |
|             | 'round(double)' → 'long'               | 'long'        | Rounds a 'double' to nearest whole number    |
| 'max', 'min'| 'max(int,int)', 'max(long,long)', etc.| same as args  | Returns larger (or smaller) of two values    |




14.2 Rounding: 'Math.round()'

Rounds a floating-point value to the nearest integer, returning the appropriate integral type.

'''java
int r1 = Math.round(1.1F);     // uses float version → 1
long r2 = Math.round(1.6);     // uses double version → 2
'''

- 'round(float)' returns 'int'  
- 'round(double)' returns 'long'  




14.3 Ceiling and Floor

# 'Math.ceil(double)'

Returns the smallest integer ≥ the argument, as a 'double'.

'''java
double d = 1.1;
int c = (int) Math.ceil(d);   // (double)2.0 cast to int → 2
'''

- Always returns a whole-number value, but as 'double', so you’ll often cast to 'int' or 'long'.

# 'Math.floor(double)'

Returns the largest integer ≤ the argument, as a 'double'.

'''java
int f = (int) Math.floor(1.9);  // floor(1.9)→1.0 → cast → 1
'''




14.4 Maximum and Minimum

Find the larger or smaller of two values. Each primitive type has its overload:

'''java
int bigger  = Math.max( 10,  20);  // 20
double small = Math.min(2.5, 1.7); // 1.7
'''




14.5 Generating Random Numbers

# 'Math.random()'

- Returns a 'double' in the range '[0.0, 1.0)' (zero inclusive, one exclusive).
- No parameters.

'''java
double r = Math.random();  // e.g., 0.374829365
'''



14.6 Scaling Random to a Range

To get a random number between 0 and N ('0 ≤ value < N'):

'''java
double scaled = Math.random() * 100;  // 0.0 ≤ scaled < 100.0
'''



14.7 Rounding or Casting a Random Value

# Using 'round()' then cast

'''java
long temp = Math.round(Math.random() * 100);  
int rnd   = (int) temp;  // safe: 0–100  
'''

# Direct explicit cast

Be careful—casting only the 'random()' call drops the fraction before scaling:

'''java
int bad = (int) Math.random() * 100;  
// Evaluates as ((int)Math.random()) * 100 → 0 * 100 → always 0
'''

Wrap the entire expression in parentheses:

'''java
int good = (int) (Math.random() * 100);  
// 0 ≤ good < 100
'''




14.8 Pipeline Diagram for Random Integer

'''
Math.random() 
     │  returns double in [0,1)
     ↓
× 100  → double in [0,100)
     ↓
round() → long in [0,100]
     ↓
cast to int  → int in [0,100]
'''

Or, for direct cast:

'''
 (int)(Math.random() * 100)
'''




14.9 Other Useful 'Math' Methods

- 'Math.abs(x)'       → absolute value  
- 'Math.pow(x,y)'     → x raised to the y power  
- 'Math.sqrt(x)'      → square root of x  
- 'Math.log(x)', 'Math.exp(x)' → natural logarithm and exponent  
- Trigonometry: 'Math.sin()', 'Math.cos()', 'Math.tan()', etc.




14.10 Key Takeaways

- No import needed for 'Math'—it’s in 'java.lang'.  
- Understand method return types (e.g., 'round(double)' returns 'long').  
- Always cast or assign to the correct type to avoid compile errors.  
- When generating random integers, remember to parenthesize the scaling before casting.  
- Explore 'Math' beyond basics for advanced operations (exponents, logarithms, trigonometry).

With these tools, you can perform precise rounding, limit values, compare numbers, and generate random data—all essential for robust Java applications.

15. Formatting Numbers: 
Formatting raw numbers into human-friendly strings is essential when displaying currencies, percentages, or other localized numeric data. Java’s 'NumberFormat' API in 'java.text' provides powerful tools to handle this cleanly and consistently.




15.1 Why Format Numbers?
  
When you present a price or a ratio to users, raw numeric values often fall short:

  
- A price of '1234567.891' is hard to read without separators.  
- A ratio of '0.1' doesn’t immediately scream “10%”.  

  
Formatting solves these:

  
- Adds currency symbols and comma separators.  
- Converts decimals into percent strings.  




15.2 Introducing 'NumberFormat'
  
The 'NumberFormat' class lives in 'java.text'. It is abstract, so you cannot do:

  
'''java
NumberFormat nf = new NumberFormat();  // Compilation error: abstract class
'''

  
Instead, 'NumberFormat' offers factory methods that return ready-to-use instances:

  
- 'NumberFormat.getCurrencyInstance()'  
- 'NumberFormat.getPercentInstance()'  
- 'NumberFormat.getInstance()' (general number formatting)  

  
These methods hide locale-specific details and produce a 'NumberFormat' object tailored for the requested style.




15.3 Abstract Classes & Factory Methods
  
Abstract Class Primer:  
- An abstract class provides structure and contracts but cannot be instantiated directly.  
- Subclasses supply concrete behavior.  

  
Factory Method Pattern:  
- A factory method is a static method that returns an instance of a subclass.  
- It centralizes object creation, often choosing the appropriate subclass based on context (e.g., locale).




15.4 Formatting Currency
  
1. Import and obtain an instance:  

   '''java
   import java.text.NumberFormat;

   NumberFormat currencyFormatter = NumberFormat.getCurrencyInstance();
   '''

2. Format a 'double' or 'long':  

   '''java
   double price = 1234567.891;
   String formatted = currencyFormatter.format(price);
   System.out.println(formatted);  
   // Output (US locale): $1,234,567.89
   '''

3. Under the hood:  

   | Feature                | Behavior                         |
   |------------------------|----------------------------------|
   | Grouping separator     | Inserts commas every three digits |
   | Decimal precision      | Defaults to two fractional digits |
   | Currency symbol        | Prepended according to locale     |

  
ASCII illustration of '$1,234,567.89':

'''
 $  1 , 2 3 4 , 5 6 7 . 8 9
↑      ↑       ↑     ↑   ↑
Symbol group   group decimal fractions
'''




15.5 Formatting Percentages

  
1. Obtain a percent formatter:  

   '''java
   NumberFormat percentFormatter = NumberFormat.getPercentInstance();
   '''

2. Format a fractional value:  

   '''java
   double ratio = 0.1;
   String pct = percentFormatter.format(ratio);
   System.out.println(pct);  
   // Output: 10%
   '''

3. The percent formatter multiplies by 100 and appends a '%' symbol, rounding to no decimal places by default.




15.6 Overloaded 'format()' Methods

  
'NumberFormat.format()' is overloaded to accept various numeric types:

  
- 'String format(double number)'  
- 'String format(long number)'  
- 'String format(BigInteger number)'  

  
Choose the signature matching your data type to avoid implicit conversions.




15.7 Method Chaining for Conciseness

  
If you only use your formatter once, you can skip the local variable and chain calls directly:

'''java
String result = NumberFormat
                   .getPercentInstance()  // Factory method
                   .format(0.1);          // Overloaded format
System.out.println(result);           // 10%
'''

Diagram of the chain:

'''
NumberFormat.getPercentInstance()
          ↓
    (NumberFormat object)
          ↓
          .format(0.1)
          ↓
      "10%" (String)
'''



15.8 IDE Tip: Safe Renaming with Refactoring

  
When you decide to rename a variable like 'currencyFormatter' → 'percentFormatter', avoid manual edits. In IntelliJ IDEA:

  
1. Place cursor on identifier.  
2. Press Shift + F6 (Rename refactoring).  
3. Type new name; all references update instantly.  
4. Press Enter to confirm.  

  
This preserves code correctness and speeds up renaming across multiple files.




15.9 Beyond Currency & Percent

  
The 'NumberFormat' family also includes:

  
- 'NumberFormat.getIntegerInstance()' for whole numbers only.  
- Custom minimum/maximum fraction digits:  
  '''java
  NumberFormat nf = NumberFormat.getInstance();
  nf.setMinimumFractionDigits(3);
  nf.setMaximumFractionDigits(5);
  '''
- Locale-specific variants:  
  '''java
  NumberFormat euroFmt = NumberFormat.getCurrencyInstance(Locale.GERMANY);
  '''




Key Takeaways

  
- Import 'java.text.NumberFormat' and use factory methods—never 'new'.  
- Pick the correct instance: currency, percent, integer, or general number.  
- Understand overloads of 'format()'.  
- Use method chaining for single-use formatters.  
- Leverage IDE refactoring to rename safely.  

With these concepts, you can ensure every numeric value in your Java applications is presented clearly, accurately, and in a style your users expect.

16. Reading Input: 
Reading input from the user is fundamental for interactive Java applications. The 'Scanner' class in 'java.util' makes it straightforward to parse primitive types and strings from various sources, most commonly the terminal.




16.1 Overview:

When building a console-based Java program, you typically:

- Import and instantiate a 'Scanner' to read from standard input ('System.in').  
- Prompt the user with 'System.out.print' or 'println'.  
- Call 'scanner.nextXxx()' methods to parse input tokens or entire lines.  
- Handle mismatches and trailing newlines carefully.  




16.2 Scanner Class Essentials:

16.2.1 Importing and Instantiating

'''java
import java.util.Scanner;

Scanner scanner = new Scanner(System.in);
'''

You must import 'java.util.Scanner'. Instantiating with 'System.in' ties the scanner to the terminal input stream.

 16.2.2 System.in and System.out

- 'System.in' is an 'InputStream' representing keyboard input.  
- 'System.out' is a 'PrintStream' for writing to the terminal.  
- Use 'print()' vs 'println()' to control line breaks when prompting.




16.3 Reading Primitive Types:

The scanner provides a set of 'nextXxx()' methods, each parsing a different primitive type:

- 'nextByte()', 'nextShort()', 'nextInt()', 'nextLong()'  
- 'nextFloat()', 'nextDouble()'  
- 'nextBoolean()'  

'''java
System.out.print("Age: ");
byte age = scanner.nextByte();
System.out.println("You are " + age);
'''

- If the user types a non-byte value (e.g., '20.1'), 'InputMismatchException' is thrown.  
- Always match your prompt to the 'nextXxx()' call to avoid runtime errors.




16.4 Prompting the User:

Choosing between 'print()' and 'println()' affects where user input appears:

'''java
System.out.println("Age: ");  // prints label and moves to next line
System.out.print("Age: ");    // prints label, stays on same line
'''

Use 'print()' when you want the user’s input cursor to follow the prompt on the same line.




16.5 Handling Parsing Errors:

A mismatched token triggers an exception:

'''
Exception in thread "main" java.util.InputMismatchException
'''

Best practices:

- Validate input with 'scanner.hasNextXxx()' before calling 'nextXxx()'.  
- Catch 'InputMismatchException' and reprompt the user.  
- Consider reading everything as a string and parsing manually for more control.




16.6 Reading Strings:

16.6.1 'next()' vs 'nextLine()'

- 'next()': reads the next token (delimited by whitespace).  
- 'nextLine()': reads the entire line, including spaces, up to the newline.

'''java
System.out.print("Name: ");
String firstName = scanner.next();      // only the first word
String fullName  = scanner.nextLine();  // rest of the line, possibly empty
'''


16.6.2 Tokens and Delimiters

Scanner splits input at default delimiters (spaces, tabs, newlines).  

'''
Input:   Mosh Hamadani
Tokens: [Mosh] [Hamadani]
'''

Calling 'next()' twice retrieves both tokens; 'nextLine()' retrieves the whole string.




16.7 Trimming Whitespace

If users accidentally type leading or trailing spaces, use 'String.trim()':

'''java
String name = scanner.nextLine().trim();
'''

This removes all whitespace before the first non-space and after the last non-space character.




16.8 Method Chaining

For one-off reads, you can chain factory and parsing calls:

'''java
String result = new Scanner(System.in)
                    .nextLine()
                    .trim();
'''

Diagram of chaining:

'''
new Scanner(System.in)
       ↓
   scanner.nextLine()
       ↓
    String.trim()
       ↓
     cleaned String
'''




16.9 Best Practices

- Always close your scanner when done: 'scanner.close()'.  
- Avoid mixing 'nextLine()' with other 'nextXxx()' calls without clearing the newline.  
- Use 'hasNextXxx()' checks to make your program robust against invalid input.  
- For complex input flows, consider wrapping prompts and parsing into reusable methods.

With these tools, you can build interactive Java programs that read and validate user input reliably.

public class Main {
	public static void main(String[] args) {
		Scanner scanner = new Scanner(System.in);

17. Project — Mortgage calculator:
Build a console app that asks for loan details and prints the monthly mortgage payment, neatly formatted as currency. You’ll combine types, input, math, and formatting from this section into one cohesive, real-world program.



Problem statement and inputs:
- Goal: Compute and display the fixed monthly mortgage payment for a loan, formatted as currency (e.g., $472.81).
- Inputs (from user):
  - Principal: total loan amount (e.g., 100000)
  - Annual interest rate: in percent (e.g., 3.92)
  - Period: number of years (e.g., 30)
- Output: A single line with the monthly payment as currency.

> Tip: Validate input to keep your program robust. Reasonable defaults:
> - Principal: [1,000 … 1,000,000]
> - Annual interest rate: (0 … 30]
> - Period (years): [1 … 30]
> Adjust ranges to your context.




Mortgage formula explained:

- Symbols:
  - \(P\): Principal (loan amount)
  - \(r\): Monthly interest rate
  - \(n\): Total number of monthly payments
  - \(M\): Monthly payment

- Conversions:
  - Monthly rate: \(r = \dfrac{\text{annualRate}}{100 \cdot 12}\)
  - Payments: \(n = \text{years} \cdot 12\)

- Formula (fixed-rate amortized loan):
  \[
  M = P \cdot \frac{r \cdot (1 + r)^{n}}{(1 + r)^{n} - 1}
  \]

- Zero-interest edge case: If \(r = 0\), then \(\;M = \dfrac{P}{n}\)

- Implementation note: Use 'Math.pow(1 + r, n)' for \((1 + r)^n\).




Worked example (sanity check):

- Given:  
  - Principal: \(P = 100{,}000\)  
  - Annual interest: \(3.92\%\)  
  - Years: \(30\)
- Compute:  
  - Monthly rate: \(r = 0.0392 / 12 \approx 0.0032666667\)  
  - Payments: \(n = 30 \cdot 12 = 360\)  
  - Growth factor: \(g = (1 + r)^n \approx \text{use Math.pow}\)
- Monthly payment:  
  \[
  M = 100{,}000 \cdot \frac{0.0032666667 \cdot g}{g - 1} \approx 472.81
  \]
- Expected output: 'Mortgage: $472.81' (locale-dependent symbol/format)

package com.codewithmosh;

import java.text.NumberFormat;
import java.util.Locale;
import java.util.Scanner;

public class Main {
    // Constants improve readability and reduce “magic numbers”
    private static final byte  MONTHS_IN_YEAR = 12;
    private static final byte  PERCENT = 100;

    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        // Principal
        int principal = 0;
        while (true) {
            System.out.print("Principal ($1K - $1M): ");
            if (scanner.hasNextInt()) {
                principal = scanner.nextInt();
                if (principal >= 1_000 && principal <= 1_000_000) break;
            } else {
                scanner.next(); // consume invalid token
            }
            System.out.println("Please enter a value between 1,000 and 1,000,000.");
        }

        // Annual interest rate
        double annualRate = 0;
        while (true) {
            System.out.print("Annual Interest Rate (0 - 30]: ");
            if (scanner.hasNextDouble()) {
                annualRate = scanner.nextDouble();
                if (annualRate > 0 && annualRate <= 30) break;
            } else {
                scanner.next();
            }
            System.out.println("Please enter a value greater than 0 and up to 30.");
        }

        // Period (years)
        int years = 0;
        while (true) {
            System.out.print("Period (Years) [1 - 30]: ");
            if (scanner.hasNextInt()) {
                years = scanner.nextInt();
                if (years >= 1 && years <= 30) break;
            } else {
                scanner.next();
            }
            System.out.println("Please enter a value between 1 and 30 years.");
        }

        // Compute
        double monthlyRate = annualRate / PERCENT / MONTHS_IN_YEAR;
        int numberOfPayments = years * MONTHS_IN_YEAR;

        double mortgage;
        if (monthlyRate == 0) {
            mortgage = principal / (double) numberOfPayments;
        } else {
            double factor = Math.pow(1 + monthlyRate, numberOfPayments);
            mortgage = principal * (monthlyRate * factor) / (factor - 1);
        }

        // Format as currency (uses default locale; customize with Locale if needed)
        NumberFormat currency = NumberFormat.getCurrencyInstance(Locale.getDefault());
        String mortgageFormatted = currency.format(mortgage);

        System.out.println("Mortgage: " + mortgageFormatted);

        scanner.close();
    }
}
'''

        int y = 1;

        System.out.println(x == y);  // true

        // Inequality check
        System.out.println(x != y);  // false

        // Relational checks
        y = 2;
        System.out.println(x < y);   // true
        System.out.println(x <= y);  // true
        System.out.println(x > y);   // false
        System.out.println(x >= y);  // false
    }
}
'''




2.9 Key Takeaways
- Always remember: '==' is for equality, '=' is for assignment.
- All comparison operators return a boolean result.
- Comparisons are fundamental for conditional statements and loops.
- You can chain or combine comparisons using logical operators (next topic).

3. Logical Operators: 

3.1 Overview

In Java, logical operators are used to combine or manipulate boolean expressions (expressions that evaluate to 'true' or 'false').  
They allow you to implement complex decision-making rules by joining multiple conditions together.

Logical operators are evaluated in the context of short-circuit evaluation, meaning Java may skip evaluating parts of an expression if the result can already be determined.




3.2 The Three Main Logical Operators

| Operator | Name               | Symbol | Meaning                                                                 |
|----------|--------------------|--------|-------------------------------------------------------------------------|
| AND      | Logical AND        | '&&'   | Returns 'true' only if *both* operands are 'true'.                  |
| OR       | Logical OR         | '\|\|' | Returns 'true' if *at least one* operand is 'true'.                     |
| NOT      | Logical NOT        | '!'    | Reverses ('negates') the value of a boolean ('true' → 'false', etc.).   |




3.3 Logical AND ('&&')

Definition
The logical AND operator returns 'true' only when both conditions are 'true'.  
If either condition is 'false', the whole expression becomes 'false'.



Example 1 — Temperature Check
'''java
int temperature = 22;
boolean isWarm = temperature > 20 && temperature < 30;
System.out.println(isWarm); // true
'''

- Condition 1: 'temperature > 20' → '22 > 20' → 'true'
- Condition 2: 'temperature < 30' → '22 < 30' → 'true'
- Result: 'true && true' → 'true'

If 'temperature = 12':
- Condition 1 → 'false', so Java skips evaluating Condition 2 (short-circuit).
- Result: 'false'.



Truth Table for '&&'
| A     | B     | A && B |
|-------|-------|--------|
| true  | true  | true   |
| true  | false | false  |
| false | true  | false  |
| false | false | false  |




3.4 Logical OR ('||')

Definition:
The logical OR operator returns 'true' if at least one of the conditions is 'true'.  
If the first condition is 'true', Java skips evaluating the second (short-circuit).



Example 2 — Loan Eligibility (Basic)
'''java
boolean hasHighIncome = true;
boolean hasGoodCredit = true;
boolean isEligible = hasHighIncome || hasGoodCredit;
System.out.println(isEligible); // true
'''

- Rule: A person is eligible for a loan if they have high income OR good credit.
- If either 'hasHighIncome' OR 'hasGoodCredit' is 'true', the result is 'true'.



Truth Table for '||'

| A     | B     | A \|\| B |
|-------|-------|----------|
| true  | true  | true     |
| true  | false | true     |
| false | true  | true     |
| false | false | false    |




3.5 Logical NOT ('!')

Definition

The logical NOT operator reverses the value of a boolean:
- '!true' → 'false'
- '!false' → 'true'



Example 3 — Loan Eligibility with Criminal Record Check

'''java
boolean hasHighIncome = true;
boolean hasGoodCredit = true;
boolean hasCriminalRecord = false;

boolean isEligible = (hasHighIncome || hasGoodCredit) && !hasCriminalRecord;
System.out.println(isEligible); // true
'''

Explanation:
1. '(hasHighIncome || hasGoodCredit)'  
   → 'true || true' → 'true'
2. '!hasCriminalRecord'  
   → '!false' → 'true'
3. 'true && true' → 'true'

Rule Implemented:
- Applicant must (have high income OR good credit)  
- AND must NOT have a criminal record.



3.6 Operator Precedence

Order of evaluation for logical operators:
1. '!' (NOT)
2. '&&' (AND)
3. '||' (OR)

Tip: Use parentheses '()' to make conditions clear and override precedence when needed.



3.7 Visual Representation — Example 3

'''
[hasHighIncome]---- true ----\
                               >--- OR --- true ----\
[hasGoodCredit]---- true ----/                        \
                                                        >--- AND --- true --> Eligible
[hasCriminalRecord]-- false --> NOT --> true ---------/
'''



3.8 Short-Circuit Behavior

- For '&&':
  - If the first condition is 'false', Java skips evaluating the second.
- For '||':
  - If the first condition is 'true', Java skips evaluating the second.

Why?
- Saves computation time.
- Prevents unnecessary or unsafe method calls.




3.9 Common Use Cases

- Validating input:
  '''java
  if (age > 18 && age < 65) { ... }
  '''
- Eligibility rules:
  '''java
  if (isMember || hasCoupon) { ... }
  '''
- Negating conditions:
  '''java
  if (!isVerified) { requestVerification(); }
  '''



3.10 Complete Code Demo

'''java

public class Main {
    public static void main(String[] args) {
        // AND Example
        int temperature = 22;
        boolean isWarm = temperature > 20 && temperature < 30;
        System.out.println(isWarm); // true

        // OR Example
        boolean hasHighIncome = true;
        boolean hasGoodCredit = true;
        boolean isEligible = hasHighIncome || hasGoodCredit;
        System.out.println(isEligible); // true

        // AND + OR + NOT Example
        boolean hasCriminalRecord = false;
        isEligible = (hasHighIncome || hasGoodCredit) && !hasCriminalRecord;
        System.out.println(isEligible); // true
    }
}
'''



3.11 Key Takeaways

- '&&' (AND) → All conditions must be true.  
- '||' (OR) → At least one condition must be true.  
- '!' (NOT) → Reverses boolean value.  
- Short-circuiting improves efficiency and safety.  
- Parentheses improve readability and control precedence.

4. If Statements:

4.1 What Is an If Statement?

An if statement is a conditional control flow statement in Java that allows your program to make decisions.  
It executes one block of code only if a specific boolean expression evaluates to 'true'.

Key Idea:  
> Without if statements, a program would execute sequentially, without reacting to conditions.




4.2 The Basic Structure of an If Statement

# Syntax
'''java
if (booleanExpression) {
    // code block runs if condition is true
}
'''

- 'booleanExpression' → Any expression that evaluates to 'true' or 'false' (e.g., 'temp > 30').
- Curly braces '{}' → Enclose the code block to run if the condition is true.
- If braces are omitted, only the first statement after the 'if' is executed conditionally.




4.3 Extending If Statements — Else If & Else

To handle multiple possible outcomes, we extend the 'if' statement:

# General Form:
'''java
if (condition1) {
    // Executes if condition1 is true
} else if (condition2) {
    // Executes if condition1 is false AND condition2 is true
} else {
    // Executes if none of the above conditions are true
}
'''




4.4 Practical Example — Temperature Messages

Problem:  
Write a program that:
- If temperature > 30 → display:
  - "It's a hot day"
  - "Drink water"
- Else if temperature > 20 and ≤ 30 → display:
  - "Beautiful day"
- Else → display:
  - "Cold day"

Implementation:
'''java
int temp = 32;

if (temp > 30) {
    System.out.println("It's a hot day");
    System.out.println("Drink water");
} else if (temp > 20) {
    System.out.println("Beautiful day");
} else {
    System.out.println("Cold day");
}
'''




4.5 Code Execution Flow

Example with 'temp = 32':
1. 'temp > 30'? → true  
   Runs block:  
   '''
   It's a hot day
   Drink water
   '''
2. 'else if' skipped because first condition was true.
3. 'else' skipped because a previous branch already ran.




4.6 Boolean Expression Simplification

Original 'else if':
'''java
else if (temp > 20 && temp <= 30)
'''

Why it can be simplified:
- If execution reaches this branch, the first condition ('temp > 30') has already failed.  
  Therefore, 'temp <= 30' is automatically true.
- Simplified form:
'''java
else if (temp > 20)
'''




4.7 Braces — When to Use Them

- Mandatory when you have multiple statements in the block.
- Optional for single statements — but:
  - Pros of omitting: Less visual noise, cleaner look.
  - Cons of omitting: Can cause bugs when adding statements later and forgetting braces.
- Industry best practice: Many teams require always adding braces for clarity and maintainability.

Example without braces:
'''java
if (temp > 20)
    System.out.println("Beautiful day");
'''

Example with braces:
'''java
if (temp > 20) {
    System.out.println("Beautiful day");
}
'''




4.8 Formatting for Readability

Formatting influences code symmetry and readability:
- Option 1: Inline style
  '''java
  if (temp > 30) {
      ...
  } else if (temp > 20) {
      ...
  } else {
      ...
  }
  '''
- Option 2: New-line aligned style
  '''java
  if (temp > 30) {
      ...
  }
  else if (temp > 20) {
      ...
  }
  else {
      ...
  }
  '''
  Keeps all clauses visually aligned at the same indentation level.




4.9 Flowchart — If-Else Logic

'''
       ┌──────────────────────┐
       │ temp > 30 ?          │
       └───────┬──────────────┘
               │Yes
               ▼
     "Hot day" + "Drink water"
               │
             [End]
               │No
               ▼
     ┌────────────────────────┐
     │ temp > 20 ?             │
     └─────────┬───────────────┘
               │Yes
               ▼
        "Beautiful day"
               │
             [End]
               │No
               ▼
         "Cold day"
'''




4.10 Common Pitfalls
1. Using '=' instead of '==' in conditions.
2. Omitting braces and later adding multiple lines → logical errors.
3. Overcomplicating conditions that can be simplified with logical reasoning.
4. Misaligned formatting making code harder to read.




4.11 Key Takeaways
- If statements let you branch program execution based on boolean conditions.
- Use else if for multiple conditions, else for a default catch-all.
- Always format code for readability and consistency.
- Simplify boolean expressions where possible.
- Consider always using braces to avoid mistakes.

5. Simplifying If Statements: 


5.1 The Context

When writing 'if' statements, beginners often use verbose patterns that can be condensed into cleaner, more expressive code.  
This tutorial shows step-by-step improvements to transform a basic 'if-else' into an elegant single-line boolean assignment.



5.2 The Initial Problem

Example:
'''java
int income = 120_000; // underscore for readability
boolean hasHighIncome;

if (income > 100_000)
    hasHighIncome = true;
else
    hasHighIncome = false;
'''



Issues with the Initial Code

1. Scoping Problem:  
   - If the variable 'hasHighIncome' is declared *inside* the 'if' block:  
     '''java
     if (income > 100_000) {
         boolean hasHighIncome = true; // only exists inside this block
     }
     '''  
     You cannot use it outside that block → leads to "Cannot resolve symbol" error.

2. Verbosity:  
   - The code explicitly assigns 'true' or 'false' based on a condition — but the condition itself is already a boolean expression.

3. Readability:  
   - While correct, it’s unnecessarily long and not idiomatic for experienced Java developers.




5.3 Step 1 — Declare Variable Outside and Assign Inside

'''java
int income = 120_000;
boolean hasHighIncome;

if (income > 100_000)
    hasHighIncome = true;
else
    hasHighIncome = false;
'''

- Variable is accessible after the 'if' statement.
- Still verbose and has duplicate assignments.




5.4 Step 2 — Initialize with a Default Value

Instead of using an 'else' to assign 'false', set the variable to 'false' initially, then update it to 'true' if condition passes.

'''java
int income = 120_000;
boolean hasHighIncome = false;

if (income > 100_000)
    hasHighIncome = true;
'''

- Removes the 'else' clause.
- Still, there’s duplication in assigning 'true' only inside an 'if'.




5.5 Step 3 — Directly Assign the Boolean Expression

Since '(income > 100_000)' already evaluates to a boolean value:
- If the expression is 'true', assign 'true'.
- If it’s 'false', assign 'false'.

You can assign the expression directly to the variable:

'''java
int income = 120_000;
boolean hasHighIncome = income > 100_000;
'''

Why this is better:
- No 'if' statement required.
- Shorter, cleaner, and easier to read.
- Avoids redundant code.




5.6 Step 4 — Adding Parentheses for Clarity (Optional)

Even though parentheses are not required (due to operator precedence), they can improve readability by making it clear that the right-hand side is one boolean expression:

'''java
int income = 120_000;
boolean hasHighIncome = (income > 100_000);
'''




5.7 Visual Breakdown of the Final Code

'''
[ income > 100_000 ] → evaluates to true/false
            │
            ▼
   assigned directly to
    hasHighIncome variable
'''




5.8 Best Practices

- Prefer concise boolean assignments when no extra logic is needed.
- Use meaningful variable names ('hasHighIncome', not 'hhi').
- Parentheses can be added when they make the expression’s intent clearer.
- Avoid unnecessary branching ('if-else') for straightforward boolean evaluations.



5.9 Final Clean Version

'''java
package com.codewithmosh;

public class Main {
    public static void main(String[] args) {
        int income = 120_000;
        boolean hasHighIncome = (income > 100_000);
        System.out.println(hasHighIncome); // true
    }
}
'''



5.10 Key Takeaways

1. Boolean expressions ('x > y', 'a == b', etc.) already produce 'true'/'false' values — no need to wrap in verbose 'if-else' assignments.
2. This technique reduces lines of code while improving clarity.
3. Parentheses are optional but encouraged for readability in complex statements.
4. This is the professional, idiomatic way to handle simple boolean assignments.

6. The Ternary Operator: 


6.1 Introduction

The ternary operator in Java is a compact, elegant way to write conditional assignments.  
Instead of writing multiple lines of 'if-else' logic, you can assign a value to a variable based on a condition — in a single line.




6.2 The Real-World Scenario

We’ll build upon the example from the previous lesson:

Problem Statement:  
- We have an integer variable 'income' representing a customer’s annual income.
- Business rule:
  - If 'income > 100,000' → classify as '"First"'
  - Else → classify as '"Economy"'




6.3 The Naïve If-Else Implementation

'''java
int income = 120_000; // underscores for readability
String className;

if (income > 100_000)
    className = "First";
else
    className = "Economy";
'''

 Drawbacks
- Verbose — even for a simple two-way assignment.
- Code has more visual clutter than needed.
- Professional developers prefer concise, expressive code when appropriate.




6.4 First Simplification — Default Initialization

Instead of using an 'else' to set the default, we can initialize first:

'''java
String className = "Economy";
if (income > 100_000)
    className = "First";
'''

- More concise.
- Eliminates 'else' block.
- Still two separate statements and not the most compact form.




6.5 Why We Can’t Use the Previous Boolean Assignment Trick

In the last tutorial, we directly assigned a boolean expression to a boolean variable:
'''java
boolean hasHighIncome = (income > 100_000);
'''
That worked because:
- Condition produced a boolean.
- Variable type was boolean.

Here:
- Variable type is String.
- We need to assign '"First"' or '"Economy"', depending on the boolean result — not the boolean itself.
- This is where the ternary operator fits perfectly.




6.6 Syntax of the Ternary Operator

The ternary operator is also called the conditional operator.  
It has three operands, hence "ternary":

'''java
variable = (condition) ? valueIfTrue : valueIfFalse;
'''

 Components:
1. Condition (must evaluate to 'true' or 'false')
2. Value if true (returned when condition is 'true')
3. Value if false (returned when condition is 'false')




6.7 Applying the Ternary Operator to Our Example

'''java
int income = 120_000;
String className = (income > 100_000) ? "First" : "Economy";
'''

How it works:
- '(income > 100_000)' → evaluates to 'true'
- Since condition is 'true', '"First"' is chosen and assigned to 'className'.
- If it were 'false', '"Economy"' would be assigned.




6.8 Execution Flow Diagram

'''
       Condition: income > 100_000
                 /          \
               true         false
               /              \
          "First"           "Economy"
                 \          /
                 Assigned to className
'''




6.9 When to Use the Ternary Operator

✅ Ideal for:
- Compact assignments where there are only two possible values.
- Situations where clarity is not sacrificed by brevity.

⚠️ Avoid when:
- You have multiple conditions — nested ternary operators can become unreadable.
- Complex logic — use 'if-else' for clarity in those cases.




6.10 Best Practices

- Always use parentheses around the condition for clarity, even if not technically required.
- Keep each branch ('valueIfTrue' and 'valueIfFalse') simple.
- Ensure readability is maintained — short does not always mean better.




6.11 Full Example Code

'''java
package com.codewithmosh;

public class Main {
    public static void main(String[] args) {
        int income = 120_000;
        String className = (income > 100_000) ? "First" : "Economy";
        System.out.println(className); // Output: First
    }
}
'''



6.12 Key Takeaways

- The ternary operator is a shorthand for 'if-else' when assigning values.
- It works with any type, not just booleans — as long as both result expressions are compatible with the variable’s type.
- Use only for simple conditions to avoid impacting maintainability.
- Great for inline initializations in constructors, method arguments, or return statements.

7. Switch Statements: 


7.1 Introduction

The 'switch' statement in Java is a multi-branch selection control statement.  
It allows you to execute different blocks of code depending on the value of a single expression.  

It is functionally similar to multiple 'if-else-if' statements but can sometimes be cleaner and more readable, especially when checking one variable against many possible constant values.



7.2 When to Use 'switch' vs 'if-else'

| Use 'switch' when…                                      | Use 'if-else' when…                                 |
|---------------------------------------------------------|-----------------------------------------------------|
| You have one variable/expression to check           | You have complex conditions involving ranges, relational or logical operators |
| All comparisons are against constant values         | Conditions depend on multiple variables or calculated expressions |
| You want readable branching without repetitive 'if' | You have a small number of conditions               |




7.3 Syntax of 'switch'

'''java
switch (expression) {
    case value1:
        // Code to execute if expression == value1
        break;
    case value2:
        // Code to execute if expression == value2
        break;
    ...
    default:
        // Code to execute if no case matches
}
'''




7.4 Key Parts of a 'switch' Statement

1. Expression  
   - Evaluated once.
   - Its result is compared to each case value.
   - Must be:
     - 'byte', 'short', 'int', 'char'
     - 'String' (Java 7+)
     - 'enum' type
     - Wrapper classes for the above types (auto-unboxed).
   - Cannot be 'long', 'float', 'double', or 'boolean'.

2. Case Labels ('case value:')  
   - Must be compile-time constants and unique.
   - Ends with a colon ':'.

3. Break Statement  
   - Terminates the 'switch' block after executing a matching case.
   - Without 'break', fall-through occurs: execution continues into the next case.

4. Default Clause  
   - Optional, runs if no case matches.
   - Often placed at the end for clarity.




7.5 Example: Role-Based Access

# If-Else Version
'''java
String role = "admin"; 

if (role.equals("admin"))
    System.out.println("You're an admin");
else if (role.equals("moderator"))
    System.out.println("You're a moderator");
else
    System.out.println("You're a guest");
'''


# Switch Version
'''java
String role = "admin";

switch (role) {
    case "admin":
        System.out.println("You're an admin");
        break;
    case "moderator":
        System.out.println("You're a moderator");
        break;
    default:
        System.out.println("You're a guest");
}
'''




7.6 Flow of Execution

# Example with 'role = "admin"':
1. 'switch' evaluates 'role' → '"admin"'.
2. Matches 'case "admin":'.
3. Executes 'System.out.println("You're an admin");'.
4. Encounters 'break' → jumps out of the 'switch' block.
5. No other cases or default are run.




7.7 What Happens Without 'break'? (Fall-Through Behavior)

'''java
String role = "admin";

switch (role) {
    case "admin":
        System.out.println("You're an admin");
    case "moderator":
        System.out.println("You're a moderator");
    default:
        System.out.println("You're a guest");
}
'''
Output:
'''
You're an admin
You're a moderator
You're a guest
'''
- Why? Without 'break', Java continues executing all subsequent cases until it reaches a 'break' or the end of the switch block.
- Tip: Only omit 'break' intentionally (e.g., when grouping cases).




7.8 Grouping Multiple Cases

If multiple values should execute the same code:
'''java
int day = 6;

switch (day) {
    case 1: case 7:
        System.out.println("Weekend");
        break;
    default:
        System.out.println("Weekday");
}
'''




7.9 Using Switch with Non-String Types

Example with integer values:
'''java
int code = 1;

switch (code) {
    case 1:
        System.out.println("Option 1 selected");
        break;
    case 2:
        System.out.println("Option 2 selected");
        break;
    default:
        System.out.println("Unknown option");
}
'''




7.10 Switch Statement Rules

1. Type Restrictions  
   - Allowed: 'byte', 'short', 'int', 'char', 'String', 'enum'  
   - Not allowed: 'long', 'float', 'double', 'boolean'

2. Case Values Must Be Unique  
   - Duplicate labels cause compile-time error.

3. Case Values Must Be Constant  
   - They can be:
     - Literal constants ('"admin"', '1')
     - 'final' variables initialized with constants

4. Default Clause Is Optional  
   - But recommended for completeness.




7.11 Visual Representation

'''
switch (role)
 ├─ case "admin"     → "You're an admin"   → break
 ├─ case "moderator" → "You're a moderator"→ break
 └─ default          → "You're a guest"
'''




7.12 Final Example — String & Integer Switch

'''java
public class Main {
    public static void main(String[] args) {
        // String switch
        String role = "admin";
        switch (role) {
            case "admin":
                System.out.println("You're an admin");
                break;
            case "moderator":
                System.out.println("You're a moderator");
                break;
            default:
                System.out.println("You're a guest");
        }

        // Integer switch
        int option = 2;
        switch (option) {
            case 1:
                System.out.println("Option 1 selected");
                break;
            case 2:
                System.out.println("Option 2 selected");
                break;
            default:
                System.out.println("Invalid option");
        }
    }
}
'''




7.13 Key Takeaways

- Switch is a cleaner alternative to multiple 'if-else-if' checks against the same variable.
- Always use 'break' unless fall-through is intentional.
- 'default' ensures your code covers all possible values.
- Works with primitive integral types, 'String' (Java 7+), and 'enum' types.
- Improves code readability and maintenance when handling many discrete values.

8. Exercise - FizzBuzz: 


8. Exercise – FizzBuzz (Popular Interview Question)



8.1 Introduction & Problem Statement

The FizzBuzz problem is a classic question often used in coding interviews to test:
- Conditional logic
- Modulo operator usage
- Control flow structuring

The task:  
Write a Java program that:
1. Reads a number from the user.
2. If divisible by 5 → print '"Fizz"'.
3. If divisible by 3 → print '"Buzz"'.
4. If divisible by both 5 and 3 → print '"FizzBuzz"'.
5. Otherwise → print the number itself.




8.2 Understanding “Divisible By” in Code

To check if a number is divisible by 'n',  
use the modulus operator '%':

'''java
number % n == 0
'''
- '%' returns the remainder of a division.
- If the remainder is '0', the number is perfectly divisible.

Example:
'''
10 % 5 = 0 → divisible by 5
10 % 3 = 1 → NOT divisible by 3
'''




8.3 Reading User Input

We use the 'Scanner' class from 'java.util':

'''java
import java.util.Scanner;

Scanner scanner = new Scanner(System.in);
System.out.print("Number: ");
int number = scanner.nextInt();
'''

- 'System.in' → reads from the keyboard.
- 'nextInt()' → reads an integer.




8.4 First Attempt — Common Mistake

A straightforward but buggy implementation:

'''java
if (number % 5 == 0)
    System.out.println("Fizz");
else if (number % 3 == 0)
    System.out.println("Buzz");
else if (number % 5 == 0 && number % 3 == 0)
    System.out.println("FizzBuzz");
else
    System.out.println(number);
'''

The problem:
- If the number is divisible by both 5 and 3 (e.g., 15):
  - The first condition 'number % 5 == 0' matches → prints '"Fizz"'.
  - The '"FizzBuzz"' condition is never reached.
- This is because 'if-else-if' stops evaluating after the first 'true' condition.




8.5 Correct Approach — Order of Conditions

Rule:  
Always check the most specific condition first, followed by more generic ones.

Correct ordering:
'''java
if (number % 5 == 0 && number % 3 == 0)
    System.out.println("FizzBuzz");
else if (number % 5 == 0)
    System.out.println("Fizz");
else if (number % 3 == 0)
    System.out.println("Buzz");
else
    System.out.println(number);
'''



# Why This Works
1. The combined condition '(number % 5 == 0 && number % 3 == 0)' is tested first.
2. If true, we immediately print '"FizzBuzz"' and skip others.
3. Only if false, we check the 5-divisibility and 3-divisibility separately.



# Execution Flow Diagram

'''
          [Start]
             │
      Read number from user
             │
   Is number %5==0 && %3==0 ?
        ┌─────┴─────┐
       Yes          No
       │            │
  print "FizzBuzz"  │
                    │
            Is number %5==0 ?
              ┌───┴───┐
             Yes     No
             │        │
    print "Fizz"  Is number %3==0 ?
                  ┌───┴───┐
                 Yes     No
                 │        │
           print "Buzz"  print number
'''




8.6 Alternate Approach — Reducing Repetition (DRY Principle)

Some developers aim to avoid repeating '(number % 5 == 0)' in multiple places.

Nested-if example:
'''java
if (number % 5 == 0) {
    if (number % 3 == 0)
        System.out.println("FizzBuzz");
    else
        System.out.println("Fizz");
} else if (number % 3 == 0) {
    System.out.println("Buzz");
} else {
    System.out.println(number);
}
'''

# Trade-offs
- Pros: Avoids repeating '% 5 == 0' in two conditions.
- Cons: Introduces nested if statements, making code harder to read.
- Best practice: Prefer flat structure for clarity, even with some repetition.




8.7 Final Preferred Solution

Flat structure — easy to read & debug:
'''java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        System.out.print("Number: ");
        int number = scanner.nextInt();

        if (number % 5 == 0 && number % 3 == 0)
            System.out.println("FizzBuzz");
        else if (number % 5 == 0)
            System.out.println("Fizz");
        else if (number % 3 == 0)
            System.out.println("Buzz");
        else
            System.out.println(number);
    }
}
'''




8.8 Key Takeaways
- Order conditions from most specific to most generic in 'if-else' chains.
- '%' is the modulus operator — remainder 0 means divisible.
- Flat if-else structures are generally easier to read than deeply nested ones.
- Minor repetition is often better than sacrificing readability.
- This small exercise teaches fundamental control flow principles that scale to bigger problems.

9. For Loops: 


9.1 Introduction to Loops

In programming, there are many scenarios where we need to repeat a statement or block of code multiple times.  
Instead of duplicating code manually (which is inefficient, hard to maintain, and error-prone), Java provides loop constructs.

Java supports several loop types:
1. for loop
2. while loop
3. do…while loop
4. for-each loop

In this tutorial, we focus on the 'for' loop — ideal when the number of iterations is known in advance.




9.2 Syntax of the 'for' Loop

'''java
for (initialization; condition; update) {
    // Code to execute on each iteration
}
'''

Components:
1. Initialization — Declare and initialize a loop counter variable.
2. Condition — A boolean expression evaluated before each iteration; loop continues while this is 'true'.
3. Update — Changes the loop counter (increment, decrement, or another modification) at the end of each iteration.




9.3 Basic Example — Printing “Hello World” 5 Times

'''java
for (int i = 0; i < 5; i++)
    System.out.println("Hello World");
'''

# Execution Flow:
1. Initialization: 'int i = 0;'
2. Condition Check: Is 'i < 5'?  
   - If 'true' → execute loop body.  
   - If 'false' → exit loop.
3. Body Execution: Prints '"Hello World"'.
4. Update Step: 'i++' → increases 'i' by 1.
5. Repeat steps 2–4 until condition becomes 'false'.

---

Output:
'''
Hello World
Hello World
Hello World
Hello World
Hello World
'''




9.4 When to Use Braces '{}'

- If only one statement inside the loop → braces are optional.
- If multiple statements → braces required:

'''java
for (int i = 0; i < 5; i++) {
    System.out.print("Hello ");
    System.out.println("World");
}
'''




9.5 Loop Counter Conventions
- Common loop counter variable names: 'i', 'j', 'k'.
- Counters are usually integers ('int'), but can be other numeric types if needed.




9.6 Starting from Zero vs. One
Two common variations for running a loop five times:

Option 1 — Start from 0, Use '<'
'''java
for (int i = 0; i < 5; i++)
    System.out.println("Hello World " + i);
'''
Output:
'''
Hello World 0
Hello World 1
Hello World 2
Hello World 3
Hello World 4
'''

Option 2 — Start from 1, Use '<='
'''java
for (int i = 1; i <= 5; i++)
    System.out.println("Hello World " + i);
'''
Output:
'''
Hello World 1
Hello World 2
Hello World 3
Hello World 4
Hello World 5
'''



9.7 Reverse Order Counting
A 'for' loop can also count downwards:

'''java
for (int i = 5; i > 0; i--)
    System.out.println("Hello World " + i);
'''

Output:
'''
Hello World 5
Hello World 4
Hello World 3
Hello World 2
Hello World 1
'''




9.8 Visual Diagram — 'for' Loop Flow

'''
   ┌─────────────────────────────────┐
   │  Initialization: int i = 0      │
   └─────────────────────────────────┘
                  ↓
          ┌─────────────────────┐
          │ Condition: i < 5 ?  │
          └───────┬─────────────┘
                  │Yes
                  ▼
        Execute Loop Body
                  │
                  ▼
        ┌───────────────────┐
        │ Update: i++        │
        └───────────────────┘
                  │
                  └───> Back to Condition
                  │
                  └───> No → Exit Loop
'''



9.9 Key Points to Remember
- Use 'for' loops when iteration count is known ahead of time.
- Carefully choose initialization, condition, and update values to avoid infinite loops.
- Loop index variables can be declared inside or outside the 'for' statement.
- Readable code matters more than overly compressed code — avoid making loop headers unnecessarily complex.




9.10 Complete Demonstration Code

'''java
public class Main {
    public static void main(String[] args) {
        
        // Forward counting
        for (int i = 1; i <= 5; i++)
            System.out.println("Hello World " + i);
        
        // Reverse counting
        for (int i = 5; i > 0; i--)
            System.out.println("Hello World " + i);
    }
}
'''



9.11 Summary

- 'for' loops provide a concise, powerful way to execute repetitive tasks.
- Always ensure your loop terminates — infinite loops can crash programs.
- Experiment with different initial values, conditions, and increments/decrements to achieve desired patterns.

10. While Loops: 

10.1 Introduction

A while loop in Java is a control structure that repeats a block of code as long as a specified condition remains true.

It is functionally similar to a 'for' loop, but differs in:
- Syntax (separates initialization, condition, and update steps)
- Usage (better for cases where the number of repetitions is unknown in advance)



10.2 Syntax of a While Loop

'''java
while (condition) {
    // Code to repeat
}
'''

- condition → must be a boolean expression.
- Loop continues while condition is true.
- Condition is checked before each iteration.
- If condition is 'false' at the start → body never executes.




10.3 While Loop vs For Loop

- Use for loop when you know how many times you need to repeat something.
- Use while loop when you don’t know the number of repetitions beforehand (e.g., keep asking for input until user types '"quit"').




10.4 Example 1 — Rewriting a For Loop as a While Loop

'''java
int i = 5;

while (i > 0) {
    System.out.println("Hello World");
    i--;  // update counter
}
'''

Execution Steps:
1. Initialization: 'i = 5'
2. Condition Check: 'i > 0' → true → execute body
3. Body Execution: prints '"Hello World"'
4. Update Step: decrement 'i' by 1
5. Repeat until 'i' becomes 0 → loop ends




10.5 Example 2 — The "Unknown Iterations" Case

Scenario: Continuously prompt user for input until they type '"quit"', regardless of how many times that may be.


# Pitfall — Comparing Strings
In Java:
- Strings are reference types.
- '==' and '!=' compare memory addresses, not actual text content.
- Two '"quit"' strings in different memory locations may have different addresses → wrong results.

✅ Correct way: use '.equals()' method for value comparison.


# Using NOT ('!') to Reverse Condition
If we want to continue until input equals '"quit"', we use:
'''java
!input.equals("quit")
'''
This means "input does not equal quit".


# Case Sensitivity Issue
- '"quit"' and '"QUIT"' are not equal by default.
- Solution: use '.toLowerCase()' (or '.equalsIgnoreCase()') to normalize before comparing.




10.6 Final Implementation — Quit on Command
'''java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in); // created once (outside loop)
        String input = ""; // initial value ensures loop runs at least once

        while (!input.equals("quit")) {
            System.out.print("Input: ");
            input = scanner.next().toLowerCase(); // normalize case
            System.out.println(input); // echo back
        }
    }
}
'''




10.7 Why Scanner Should Be Outside the Loop

❌ Bad Practice:
'''java
while (true) {
    Scanner scanner = new Scanner(System.in); // re-created each iteration
}
'''
- Problem: Creates multiple scanner objects → wastes memory, can lead to resource leaks.

✅ Correct:
'''java
Scanner scanner = new Scanner(System.in); // single instance reused
while (...) {
    // use scanner here
}
'''




10.8 Execution Flow Diagram (While Loop)

'''
       ┌─────────────┐
       │ Initialization│
       └──────┬──────┘
              │
      ┌───────▼────────┐
      │ Condition true?│──No──► Exit loop
      └───────┬────────┘
              │Yes
              ▼
      Execute loop body
              │
              ▼
         Update step
              │
              └──► Repeat check
'''




10.9 Example Run

'''
Input: one
one
Input: two
two
Input: quit
quit
// Program terminates
'''




10.10 Key Takeaways

- While loops are best for indefinite repetition based on dynamic conditions.
- Always ensure loop will eventually terminate to avoid infinite loops.
- Use '.equals()' or '.equalsIgnoreCase()' for string comparison, never '=='.
- Create resources like Scanner outside of the loop to avoid unnecessary object creation.
- Normalize case ('.toLowerCase()') if you want case-insensitive checks.

11. Do..While Loops: 

11.1 Introduction

In Java, the `do…while` loop is another looping construct, very similar to the `while` loop in terms of functionality.  
However, it has one distinctive characteristic:

> The `do…while` loop will always execute its body at least once, even if the condition is false at the first check.

This is because the condition is evaluated after the loop body is executed — making it a post-test loop.




11.2 Syntax

```java
do {
    // Code to execute
} while (condition);
```

Key Points:
- The `do` keyword starts the loop.
- The loop body always runs first.
- After the body executes, the condition is checked.
- If the condition is `true` → loop repeats.
- If the condition is `false` → loop exits.
- A semicolon `;` is required after the `while(condition)` line.



11.3 Comparing `while` and `do…while`

| Feature                  | `while` Loop | `do…while` Loop |
|--------------------------|--------------|-----------------|
| Condition checked        | Before body | After body |
| Guaranteed 1st execution | ❌ No         | ✅ Yes          |
| Common usage             | When unsure if code needs to run | When code must run at least once |



# Execution Flow Diagram

While Loop:
```
Check Condition → If true → Execute Body → Repeat
If false at start → Body skipped entirely
```

Do…While Loop:
```
Execute Body → Check Condition → If true → Repeat
If false at start → Body still runs once
```



11.4 Example — Reading User Input Until `"quit"`

This example is adapted from the while loop scenario where the user is prompted repeatedly until they type `"quit"`.  


# While Loop Version
```java
Scanner scanner = new Scanner(System.in);
String input = "";

while (!input.equals("quit")) {
    System.out.print("Input: ");
    input = scanner.next().toLowerCase();
    System.out.println(input);
}
```
- Problem: If `input` starts as `"quit"`, the loop body will never execute.

---

# Do…While Version
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        String input;

        do {
            System.out.print("Input: ");
            input = scanner.next().toLowerCase(); // normalize for case-insensitive check
            System.out.println(input); // echo the input
        } while (!input.equals("quit")); // condition checked after body
    }
}
```



How This Works:
1. Step 1: Loop executes body (asks for input, stores value, prints value).
2. Step 2: After body, Java checks → `!input.equals("quit")`.
3. If `true` → loop repeats.
4. If `false` → loop ends.




11.5 Why `do…while` Always Runs at Least Once

- The condition is evaluated last.
- Even if the condition is false initially, Java has already run the body.

Example:
```java
int i = 0;
do {
    System.out.println("Runs at least once!");
} while (i > 0);
```
Output:
```
Runs at least once!
```
Even though `i > 0` is false at the start.



11.6 When to Use `do…while`

✅ Good for:
- Menu-driven programs where menu should display at least once before checking if the user wants to quit.
- User input validation — where you must prompt at least once before checking for validity.
- Games, simulations, and repeated prompts that should run at least once before confirming if the user wants to exit.

❌ Avoid when:
- The loop should only run if the condition is true initially — use a `while` loop instead.




11.7 Visual Flow Representation

```
       ┌───────────────┐
       │  Execute Body │
       └───────┬───────┘
               │
        Check Condition?
           │       │
         True     False
           │       │
           └──► Repeat
                   │
                 Exit
```



11.8 Key Differences Recap

1. `while` → Check first, run later (may run 0 times).
2. `do…while` → Run first, check later (runs ≥ 1 time).
3. Semicolon after `while(condition)` in a `do…while` loop is mandatory.



11.9 Key Takeaways

- `do…while` is rare compared to `while`, but useful in specific scenarios.
- Always runs the loop body at least once.
- Great for prompts and cases where action precedes validation.
- Be mindful of semicolon placement — it’s a common syntax error.
- Use with caution to avoid infinite loops when the exit condition isn’t properly updated inside the body.

12. Break and Continue Statements: 

12.1 Introduction

In this tutorial, we build upon the loop-based user input example from the previous lesson, focusing on fine-grained loop control using two special statements:
1. 'break' — Immediately exits a loop.
2. 'continue' — Skips the rest of the loop body for the current iteration and jumps to the next iteration.

These are flow control statements that give us extra flexibility in managing loop execution beyond standard loop conditions.




12.2 The Problem Scenario

We have a simple while loop that:
- Continuously asks for user input.
- Echoes back whatever is typed.
- Stops only when the user types '"quit"'.

# Initial Implementation
'''java
while (!input.equals("quit")) {
    System.out.print("Input: ");
    input = scanner.next().toLowerCase();
    System.out.println(input); // echoes user input
}
'''

Problem:  
When the user types '"quit"', the loop exits after printing '"quit"' to the console.  
Example output:
'''
Input: quit
quit   ← This feels odd (unwanted echo)
'''




12.3 Solution 1 — Conditional Printing Before Echo

Instead of always printing the input, check if it is not '"quit"' before echoing:

'''java
if (!input.equals("quit"))
    System.out.println(input);
'''

Now '"quit"' ends the loop without being printed:
'''
Input: quit
// loop terminates, no echo
'''




12.4 Solution 2 — Using 'break' to Exit Immediately

We can reverse the condition and use 'break' for cleaner logic:
'''java
if (input.equals("quit"))
    break; // exit loop immediately

System.out.println(input); // only runs if input ≠ "quit"
'''

# How 'break' works:
- The moment it is encountered in a loop, control jumps out of the loop entirely.
- Any statements after the 'break' inside the loop body are ignored.

Example run:
'''
Input: one
one
Input: quit
// loop ends immediately
'''




12.5 Using 'continue' to Skip Current Iteration

Scenario:
- If the user types '"pass"', we don’t want to echo it.
- But we do want to keep the loop going for the next input.

'''java
if (input.equals("pass"))
    continue; // skip echoing and move to next iteration

System.out.println(input);
'''

# How 'continue' works:
- Skips only the remaining statements in the loop body for the current iteration.
- Immediately jumps to the next loop condition check.




12.6 Combining 'break' and 'continue'

A practical example:
'''java
while (true) { // infinite loop — will rely on 'break' to exit
    System.out.print("Input: ");
    input = scanner.next().toLowerCase();

    if (input.equals("pass"))
        continue; // skip printing

    if (input.equals("quit"))
        break; // terminate loop entirely

    System.out.println(input);
}
'''


# Example Output
'''
Input: one
one
Input: pass
Input: two
two
Input: quit
// loop terminates
'''




12.7 Infinite Loops with 'while (true)'

In the second solution above, the loop condition was changed from:
'''java
while (!input.equals("quit"))
'''
to:
'''java
while (true)
'''

Why?
- Logic no longer depends on a condition in the 'while' header.
- Loop is controlled entirely by 'break' when '"quit"' is typed.

Caution:
- Always ensure that a 'break' statement is reachable, otherwise you create an infinite loop that never terminates, which can consume CPU and memory indefinitely.





12.8 Visual Flow of 'break' and 'continue'

Break:
'''
┌─────────────┐
│ Condition?  │──No──> Exit
└──────┬──────┘
       │Yes
       ▼
   Statement 1
       ▼
 if (break condition) → Exit immediately
       ▼
   Statement 2
       ▼
   Update & repeat
'''

Continue:
'''
┌─────────────┐
│ Condition?  │──No──> Exit
└──────┬──────┘
       │Yes
       ▼
   Statement 1
 if (continue condition) → Jump to loop check
       ▼
   Statement 2
       ▼
   Update & repeat
'''




12.9 Complete Final Example

'''java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        String input;

        while (true) {
            System.out.print("Input: ");
            input = scanner.next().toLowerCase();

            if (input.equals("pass"))
                continue; // skip printing

            if (input.equals("quit"))
                break; // exit loop

            System.out.println(input);
        }
    }
}
'''




12.10 Key Takeaways

- 'break': Terminates the loop immediately.
- 'continue': Skips remaining loop body for the current iteration and starts the next.
- 'while (true)' + 'break' is a common professional pattern — but only safe if 'break' is guaranteed.
- Use 'continue' to filter out unwanted cases without exiting the loop.
- Be careful with infinite loops — always have an exit strategy.

13. For-Each Loop: 

13.1 Introduction:

The for-each loop (also called the *enhanced for loop*) is the simplest and most readable way to iterate over:
- Arrays
- Collections (like 'ArrayList', 'HashSet', etc.)

It’s especially useful when:
- You need to visit every element in order.
- You don’t need the index of each element.




13.2 Why For-Each?

- Eliminates manual counter management ('i++' / 'i--').
- No need to write length checks.
- Code is shorter, more expressive, and less error-prone.




13.3 First — Iterating with a Standard For Loop

'''java
String[] fruits = {"Apple", "Mango", "Orange"};

for (int i = 0; i < fruits.length; i++)
    System.out.println(fruits[i]);
'''

Explanation:
1. Initialization: 'int i = 0'
2. Condition: Run loop while 'i < fruits.length'
3. Update: 'i++' each iteration
4. Access element: 'fruits[i]'  
   → Requires explicit index handling.

Output:
'''
Apple
Mango
Orange
'''




13.4 Now — Iterating with a For-Each Loop:

'''java
String[] fruits = {"Apple", "Mango", "Orange"};

for (String fruit : fruits)
    System.out.println(fruit);
'''

How it works:
- Syntax:  
  '''java
  for (DataType variableName : arrayOrCollection) {
      // use variableName
  }
  '''
- In each iteration:
  - 'fruit' holds the actual value of the current array element.
  - No index variable to manage.
  - Loop automatically covers all elements from start to end.

Output: (Same as before)
'''
Apple
Mango
Orange
'''




13.5 For-Each Loop — Internal Flow:

Although we don’t see an index in for-each syntax, internally Java:
- Starts from the first element ('index = 0')
- Moves sequentially to the last element
- Ends automatically after the last item

Flowchart:
'''
Start → Pick next element → Assign to loop variable → Execute body → Repeat until all processed
'''




13.6 Limitations of For-Each Loop

| Limitation | Why it happens | Example Alternative |
|------------|---------------|---------------------|
| 1. Forward-only iteration | No index → can’t go backwards | Use a 'for' loop: 'for (int i = arr.length-1; i >= 0; i--)' |
| 2. No access to the index | Loop variable holds only element value | Use 'for (int i = 0; i < arr.length; i++)' if you need both index and value |
| 3. Read-only iteration (for primitives) | Can't modify array elements directly via loop variable | Use index-based loop to assign new values |




13.7 Example — Reverse Iteration (Not Possible with For-Each)

'''java
for (int i = fruits.length - 1; i >= 0; i--)
    System.out.println(fruits[i]);
'''

Output:
'''
Orange
Mango
Apple
'''




13.8 When to Use Which Loop:

| Requirement | Best Choice |
|-------------|-------------|
| Access index number | For loop |
| Iterate backwards | For loop |
| Simple forward iteration, no index needed | For-Each loop |
| Modifying elements | Usually For loop |

'''java
import java.text.NumberFormat;
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        final byte MONTHS_IN_YEAR = 12;
        final byte PERCENT = 100;

        Scanner scanner = new Scanner(System.in);

        int principal;
        while (true) {
            System.out.print("Principal ($1K - $1M): ");
            principal = scanner.nextInt();
            if (principal >= 1_000 && principal <= 1_000_000) break;
            System.out.println("Enter a number between 1,000 and 1,000,000.");
        }

        float annualInterest;
        while (true) {
            System.out.print("Annual Interest Rate: ");
            annualInterest = scanner.nextFloat();

            System.out.println("Enter a value between 1 and 30.");

        int numberOfPayments = years * MONTHS_IN_YEAR;

        double mortgage = principal
            * (monthlyInterest * Math.pow(1 + monthlyInterest, numberOfPayments))
            / (Math.pow(1 + monthlyInterest, numberOfPayments) - 1);

        String mortgageFormatted = NumberFormat.getCurrencyInstance().format(mortgage);
        System.out.println("Mortgage: " + mortgageFormatted);
    }
}

16. Summary — Mastering Control Flow in Java

16.1 Recap — The Heart of Program Logic

In this section, we explored control flow — the mechanisms that allow us to direct the execution path of a Java program based on conditions, rules, and repetition requirements.

Control flow transforms a static sequence of statements into dynamic, decision-driven, and interactive logic, enabling our programs to:
- Make decisions.
- Implement rules.
- Repeat operations.
- Exit or skip certain executions as needed.




16.2 Core Concepts Covered

1. Comparison Operators — The Building Blocks of Conditions
- Purpose: Compare two primitive values and return a boolean result.
- Types:
  - Equality: '=='
  - Inequality: '!='
  - Greater than: '>'
  - Greater than or equal to: '>='
  - Less than: '<'
  - Less than or equal to: '<='
- Usage: Form the boolean expressions that drive decision-making logic.



2. Logical Operators — Combining Conditions

- Purpose: Join or negate boolean expressions to create more complex rules.
- Operators:
  - Logical AND → '&&' (True only if both conditions are true)
  - Logical OR → '||' (True if at least one condition is true)
  - Logical NOT → '!' (Reverses the boolean value)
- Short-Circuit Evaluation:  
  - With '&&', if the first expression is false, the second is not evaluated.
  - With '||', if the first expression is true, the second is not evaluated.
- Real-World Application: Implementing rules like:  
  '"Loan is approved if applicant has high income OR good credit AND no criminal record."'



3. Conditional Statements — Decision Making

- If-Else Chains:
  '''java
  if (condition) { ... }
  else if (anotherCondition) { ... }
  else { ... }
  '''
  - Order conditions from most specific to most generic.
  - Supports branching execution paths.
- Switch Statements:
  - Clean alternative when checking one variable against multiple constant values.
  - Supports 'byte', 'short', 'int', 'char', 'String', and 'enum' (but not 'long', 'float', 'double', 'boolean').
  - Use 'break' to prevent fall-through.




4. Loops — Repetition Structures

We studied four looping mechanisms:

| Loop Type      | When to Use | Key Characteristics |
|----------------|------------|---------------------|
| for        | Fixed repetition count known ahead of time. | Combines initialization, condition, update in one line. |
| while      | Repeat until a condition becomes false (count unknown). | Pre-condition check → may run 0 times. |
| do…while   | Repeat until a condition becomes false but ensure at least one execution. | Post-condition check → runs ≥ 1 time. |
| for-each   | Traverse arrays/collections easily. | No index access; forward-only iteration. |




5. Loop Control Statements

- 'break'
  - Immediately exits the loop, skipping any remaining iterations.
  - Often used with 'while (true)' for input loops with validation.
- 'continue'
  - Skips the remaining statements in the current iteration.
  - Jumps directly to the next loop iteration.





16.3 How These Concepts Work Together

Control flow elements chain together:
1. Comparison operators → build boolean expressions.
2. Logical operators → combine these expressions into complex rules.
3. Conditionals ('if', 'switch') → decide which path to take.
4. Loops ('for', 'while', 'do…while', 'for-each') → repeat steps as needed.
5. Loop controls ('break', 'continue') → manage execution inside loops.




16.4 Real-World Application — Mortgage Calculator

We applied all these concepts to enhance our Mortgage Calculator:
- Loops to continuously request input until valid values are entered.
- Conditionals to validate ranges for:
  - Principal
  - Interest rate
  - Loan period
- Break statements to exit loops after valid input is received.

Clean Coding: 

1. Introduction: 

Clean code is code written for humans first, machines second. As Martin Fowler puts it, any fool can write code a computer understands; good programmers write code humans can understand. In this section, we’ll extend the mortgage calculator and deliberately tame the complexity that grows as features are added, using concrete refactoring techniques and naming, structure, and clarity as our north stars.



Why clean code matters

- Clarity: Clean code communicates intent instantly; future you (and teammates) don’t need to reverse‑engineer logic.
- Changeability: Well‑structured code is easier to modify, extend, and debug without fear of breakage.
- Defect reduction: Smaller, focused units with clear contracts reduce hidden coupling and regression risk.
- Speed with safety: You move faster when the codebase guides you, not fights you.

Quick litmus test: if a new developer can understand a module’s purpose in under a minute without running it, the code is clean.




How small programs get messy

Even a simple console app can turn into a tangle as features pile on. Expect these smells to creep in:

- Long methods: One “God” main method that handles input, validation, math, and formatting.
- Magic numbers: Bare 12s and 100s for months and percent instead of named constants.
- Duplication: Repeated validation loops and range messages across inputs.
- Primitive obsession: Passing raw primitives everywhere instead of introducing domain concepts (e.g., Rate, Money).
- Conditional bloat: Nested if/else webs that hide simple rules.
- Low cohesion/high coupling: Utilities that do too much and modules that know too much about each other.

ASCII snapshot of the drift:
'''
Before:              After:
[main()]             [Main] ──▶ Orchestrates
  ├─ read inputs         ├─ InputReader
  ├─ validate            ├─ Validator
  ├─ compute             ├─ Mortgage (domain math)
  └─ format              └─ Formatter (currency, schedule)
'''




Principles we’ll practice

- Meaningful names: 
  - Intent first: 'numberOfPayments' over 'n', 'monthlyRate' over 'r'.
  - Consistent patterns: camelCase for variables/methods; UPPER_SNAKE_CASE for constants.
- Small functions:
  - Do one thing: Extract reading, validation, computing, formatting into separate, testable methods.
  - Few params: Prefer cohesive objects or pass only what’s needed.
- Single responsibility (SRP):
  - One reason to change: Input reading shouldn’t know formatting rules; calculation shouldn’t know I/O.
- DRY (Don’t Repeat Yourself):
  - Centralize rules: One validation function per input type; one currency formatter.
- YAGNI and simplicity:
  - Build for today’s needs: Add abstractions only when duplication or instability pushes you.
- Guard clauses over nesting:
  - Fail fast, flatten flow: Return early on invalid states to avoid pyramids of doom.
- Cohesion and coupling:
  - Tight inside, loose outside: Keep related logic together; expose minimal, clear interfaces.
- Expressive boundaries:
  - Types tell truth: Constants for 12 and 100; maybe lightweight value objects later ('Money', 'Rate').
- Automated formatting & static checks:
  - Let tools help: Consistent style and early warnings reduce cognitive load.



Refactoring mindset and workflow

- Boy Scout Rule: Always leave the code a bit cleaner than you found it.
- Small, safe steps:
  - 1) Identify a smell, 2) Write/keep a quick check, 3) Refactor, 4) Re-run checks.
- Red–Green–Refactor:
  - Red: Reproduce behavior or expected output (e.g., known mortgage result).
  - Green: Make it pass with minimal changes.
  - Refactor: Improve structure without changing behavior.
- Prefer extractions over rewrites:
  - Extract Method / Extract Variable / Introduce Parameter Object are your best friends.
- Name it right, then code it:
  - Renaming clarifies intent and often reveals the next extraction opportunity.




How we’ll evolve the mortgage calculator

- From monolith to modules:
  - InputReader: prompts and reads inputs.
  - Validator: reusable rules for principal, rate, years.
  - Mortgage: core math and, later, payment schedule (amortization).
  - Formatter: currency and aligned tabular schedule output.
- From duplication to reuse:
  - One loop pattern for validation with customizable prompts and ranges.
- From magic numbers to constants:
  - 'MONTHS_IN_YEAR', 'PERCENT', and maybe 'MIN/MAX' constraints.
- From ad-hoc prints to APIs:
  - Clear methods like 'calculateMonthlyPayment()', 'generateSchedule()', 'formatCurrency(amount)'.

High-level flow we’ll target:

 ├─ principal = InputReader.readPrincipal()

2. Clean coding

Clean code is code that reads like a clear explanation of the problem. It minimizes cognitive load, isolates responsibilities, and makes change safe. As your program grows, organizing it into small, well‑named, reusable chunks turns chaos into clarity.




Why clean code matters

- Comprehension: Clean structure lets you understand intent quickly without running the program.
- Change safety: Small, focused units with clear contracts reduce the risk of breaking other parts.
- Reuse and extension: Well‑factored pieces can be composed, reused, and extended with minimal friction.
- Debug velocity: When logic is localized and names are descriptive, issues surface and fix faster.

> Analogy: A tidy toolbox vs. a tangled drawer. The job isn’t just doable—it’s faster, safer, and less frustrating.



How code gets messy (and how to notice)

- Long methods:  
  Smell: One “God” method that handles I/O, validation, math, and formatting.  
  Impact: Hard to read, test, or change in isolation.
- Magic numbers/strings:  
  Smell: Bare 12s, 100s, “1K–1M” scattered.  
  Impact: Intent obscured; inconsistencies multiply. Prefer 'MONTHS_IN_YEAR', 'PERCENT', 'MIN_PRINCIPAL', etc.
- Duplication (DRY violations):  
  Smell: Repeated validation loops and messages.  
  Impact: Fixes must be made in many places; drift ensues.
- Primitive obsession:  
  Smell: Passing raw primitives everywhere ('double rate', 'int principal') with ad‑hoc rules in callers.  
  Impact: Rules scatter; domain meaning fades. Consider helper methods or small value types later.
- Deep nesting:  
  Smell: Pyramid of 'if/else' and loops within loops.  
  Impact: Flow is hard to follow; edge cases hide. Prefer guard clauses and early returns.
- Low cohesion/high coupling:  
  Smell: Modules/classes doing too much or knowing too much about others.  
  Impact: Changes ripple unpredictably.

Quick visual of drift:
'''
Before (tangled):
main()
 ├─ read inputs
 ├─ validate
 ├─ compute
 └─ format & print

After (tidy):
Main (orchestrate)
 ├─ Input.readPrincipal/Rate/Years
 ├─ Mortgage.calculateMonthlyPayment
 └─ Format.currency + Printer
'''




Principles you’ll apply

- Meaningful names:  
  Guideline: Names state intent, not type or mechanics (e.g., 'numberOfPayments', 'monthlyRate').  
  Consistency: camelCase for vars/methods; UPPER_SNAKE_CASE for constants.
- Small, single‑purpose functions (SRP):  
  Guideline: Each method does one thing; its name is a truthful summary.  
  Outcome: Easier testing and reuse.
- DRY (Don’t Repeat Yourself):  
  Guideline: Centralize rules (validation ranges, currency formatting).  
  Outcome: One change updates all usages.
- Avoid magic numbers/strings:  
  Guideline: Replace literals with named constants close to use.  
  Outcome: Self‑documenting code.
- Guard clauses over nesting:  
  Guideline: Fail fast and return early to flatten control flow.  
  Outcome: Linear, readable logic.
- Pure over impure (when possible):  
  Guideline: Make calculations free of side effects; isolate I/O at boundaries.  
  Outcome: Deterministic, testable core.
- Cohesion and coupling:  
  Guideline: Keep related logic together; keep modules loosely connected via small interfaces.  
  Outcome: Localized changes.




Applying this to the mortgage calculator

- Identify responsibilities (decompose):
  - Input: Prompting and reading values.
  - Validation: Enforcing ranges and rules.
  - Calculation: Mortgage math and, later, amortization.
  - Formatting/Output: Currency and tabular schedules.

- Extract methods (first pass):
  - Input methods:  
    - 'readPrincipal(scanner)'  
    - 'readAnnualRate(scanner)'  
    - 'readYears(scanner)'
  - Calculation:  
    - 'calculateMonthlyPayment(principal, annualRate, years)'
  - Formatting:  
    - 'formatCurrency(amount)'

- Centralize constants:
  - 'MONTHS_IN_YEAR', 'PERCENT', 'MIN_PRINCIPAL', 'MAX_PRINCIPAL', 'MIN_RATE', 'MAX_RATE', 'MIN_YEARS', 'MAX_YEARS'.

- Unify validation pattern:
  - A single do‑until‑valid loop shape with parameterized prompts and ranges.
  - Optional: a small helper like 'readInRange(prompt, min, max, reader)'.

- Separate concerns:
  - Keep UI (prompts/prints) out of calculation functions.
  - Keep calculation free of I/O and formatting.

Architecture snapshot:
'''
Main
 ├─ principal = Input.readPrincipal(scanner)
 ├─ rate      = Input.readAnnualRate(scanner)
 ├─ years     = Input.readYears(scanner)
 ├─ payment   = Mortgage.calculateMonthlyPayment(principal, rate, years)
 └─ Printer.println("Mortgage: " + Format.currency(payment))
'''




Refactoring playbook you’ll use

- Extract Method:  
  Use when: A block can be named and reused (e.g., reading principal).  
  Result: 'main()' becomes orchestration, not implementation.
- Extract Variable:  
  Use when: Clarify intent of sub‑expressions (e.g., 'growthFactor = Math.pow(1 + r, n)').  
  Result: Fewer mental stack frames.
- Introduce Parameter Object (later):  
  Use when: Too many related parameters travel together (e.g., 'principal', 'rate', 'years').  
  Result: Clearer boundaries.
- Replace Magic Number with Constant:  
  Use when: Literals convey rules.  
  Result: Declarative code.
- Inline Temporary (selectively):  
  Use when: A variable adds no clarity.  
  Result: Leaner code.
- Guard Clauses:  
  Use when: Early exits clarify flows (e.g., invalid input → re‑prompt).

Mini‑workflow:
1. Pin behavior: Keep a known input/output (e.g., 100,000 @ 3.92% for 30y → ≈ $472.81).
2. Extract small pieces one by one.
3. Rename for intent.
4. Run check after each step.
5. Repeat.




Heuristics and checklists

- Method checklist:
  - Single purpose: Does the name fully describe the body?
  - Short: Typically 3–10 lines; consider extracting longer ones.
  - Few parameters: Three or fewer; otherwise consider grouping.
  - No side effects (if possible): Especially for calculations.

- Naming checklist:
  - Intent first: 'readAnnualRate' over 'getRate'.
  - Domain terms: 'principal', 'amortization', 'paymentSchedule'.
  - Avoid abbreviations: Unless ubiquitous ('min', 'max').

- Formatting checklist:
  - Consistent braces and spacing.
  - Logical grouping with blank lines.
  - Align related declarations and constants.

- Duplication checklist:
  - Spot repeated loops, ranges, and messages.
  - Extract to a helper or constant once pattern stabilizes.

Anti‑patterns to avoid

- “Just one more thing” in main: Grows into an untestable blob.
- Hidden rules: Validation spread across callers.
- Over‑engineering early: Premature classes/abstractions without duplication pressure.
- Clever code: If it needs a comment to explain a trick, prefer a clearer rewrite.

3. Creating Methods: 

3.1 Why Create Methods?

Until now, all our logic has been inside the 'main()' method.  
This works for very small programs (~10–20 lines), but quickly becomes messy as the codebase grows.

Problems with writing everything in 'main()':
- Difficult to read and understand.
- Repetition of the same logic in multiple places.
- Hard to maintain — a change in one place requires multiple edits.
- Testing becomes harder since all logic is mixed together.

Solution: Break code into methods — reusable, self-contained blocks that perform a single, well-defined task.




3.2 Benefits of Creating Methods
- Reusability → Write once, call many times.
- Readability → Code becomes easier to follow — method names describe the intent.
- Maintainability → Fix or update logic in one place.
- Modularity → Isolate related code; helps with debugging and testing.
- Extensibility → Easier to add features without disturbing unrelated logic.




3.3 Anatomy of a Method in Java
A method typically consists of:

'''
accessModifier   static/non-static   returnType   methodName(parameters) {
    // method body
}
'''


Key Parts Explained:

1. Access Modifier:  
   - 'public': Accessible from anywhere.
   - 'private': Accessible only within the same class.  
   *(More to be learned later in OOP sections.)*

2. Static or Non-static:
   - 'static' → Belongs to the class; called without creating an object.
   - Non-static → Belongs to an object instance.
   *(We'll explore non-static methods later in OOP.)*

3. Return Type:
   - 'void' → No value is returned.
   - Any data type ('int', 'String', 'double', etc.) → The method must return a value of that type.

4. Method Name:
   - Use camelCase → First word lowercase, each subsequent word starts with a capital letter.
   - Should be meaningful → describes exactly what the method does.

5. Parameters:
   - Inputs the method needs to do its job.
   - Defined inside parentheses, separated by commas.
   - Each parameter has a type and a name.
   - Order matters when calling the method.

6. Method Body:
   - The block of code inside '{}' that runs when the method is called.




3.4 Example 1 — Single Parameter Method

'''java
public class Main {
    public static void main(String[] args) {
        greetUser("Mosh"); // method call
    }

    public static void greetUser(String name) { // parameter: name
        System.out.println("Hello " + name);
    }
}
'''
Flow:
- 'greetUser("Mosh")' → '"Mosh"' is argument, assigned to parameter 'name'.
- 'System.out.println("Hello " + name)' prints '"Hello Mosh"'.




3.5 Example 2 — Multiple Parameters

'''java
public static void greetUser(String firstName, String lastName) {
    System.out.println("Hello " + firstName + " " + lastName);
}
'''
Calling:
'''java
greetUser("Mosh", "Hamedani");
'''
- '"Mosh"' → copied to 'firstName'.
- '"Hamedani"' → copied to 'lastName'.

Rules:
- Number of arguments must match number of parameters.
- Type of each argument must match the parameter type.
- Order matters — values are copied based on position.




3.6 Example 3 — Returning a Value

If we want the method to produce a result (instead of printing it directly), we:
1. Change return type from 'void' to the type of the value being returned.
2. Use the 'return' keyword.
3. Capture the returned value when calling the method.

Example:
'''java
public static String greetUser(String firstName, String lastName) {
    return "Hello " + firstName + " " + lastName;
}

public static void main(String[] args) {
    String message = greetUser("Mosh", "Hamedani"); // store returned value
    System.out.println(message); // print when needed
}
'''
Advantages of returning values:
- Allows more flexibility — you can store, reuse, or further manipulate the result before displaying it.




3.7 Parameters vs. Arguments

- Parameter → Variable declared inside the method definition.
- Argument → Actual value you pass when calling the method.

Example:
'''java
public static void greetUser(String name) {  // 'name' is parameter
    System.out.println("Hello " + name);
}

greetUser("John"); // "John" is argument
'''




3.8 CamelCase Naming Convention

✅ Correct:  
'greetUser', 'calculateMortgage', 'formatCurrency'

❌ Incorrect:  
'greet_user', 'Calculate_Mortgage', 'Formatcurrency'




3.9 How Methods Improve Reusability

Instead of writing the same lines multiple times:
'''java
System.out.println("Hello Mosh");
System.out.println("Hello John");
System.out.println("Hello Mary");
'''
We can:
'''java
greetUser("Mosh");
greetUser("John");
greetUser("Mary");
'''
Benefit: One place to maintain changes — if we change greeting format, it changes everywhere.




3.10 Visual — Method Flow

'''
Call Site (main) ---> Method Definition ---> Method Execution ---> Return (if any)
'''

Example Flow:
'''
main()
  |
  ├─ greetUser("Mosh", "Hamedani")
          |
          ├─ firstName="Mosh", lastName="Hamedani"
          ├─ Create greeting string
          ├─ Return greeting or print it
'''




3.11 Best Practices

- Use meaningful method names ('calculateMortgage' > 'doStuff').
- Keep methods short and focused — they should do one thing.
- Pass only required parameters.
- Always follow camelCase naming convention.
- If method returns a value, ensure return type matches it.
- Avoid side effects in methods that are intended to be purely functional.

4. Refactoring 


4.1 What is Refactoring?

Refactoring means changing the internal structure of code without altering its external behavior.  
The purpose is to make the code:
- Cleaner — easier to read and understand.
- More maintainable — easier to update in the future.
- Reusable — easier to adapt in other projects.

Key Idea: The *functionality remains exactly the same*, but the organization, clarity, and modularity are improved.




4.2 Why Refactor?

Current Problem in the Mortgage Calculator
- The 'main()' method has grown too big:
  - Starts at line 8 and ends at line 52 → 44 lines long.
  - Best practice:  
    - Ideal length: 5–10 lines.
    - Maximum: 20 lines.
- A large method:
  - Becomes harder to navigate.
  - Mixes responsibilities (input, validation, calculation, formatting).
  - Reduces readability and reusability.




4.3 The Goal of Refactoring Here

We will break down the large 'main()' method into smaller, focused methods, so that:
- Each method handles only one responsibility (SRP — *Single Responsibility Principle*).
- Logic that belongs together stays together.
- Repetitive code is centralized instead of being duplicated.
- Future edits become safer and faster.




4.4 Step 1 — Finding Related Logic to Group

When refactoring, look for code that conceptually belongs together — even if it is physically far apart.

Example in Our Program:
- Mortgage calculation (currently near the end of 'main'):
  '''java
  double mortgage = principal
      * (monthlyInterest * Math.pow(1 + monthlyInterest, numberOfPayments))
      / (Math.pow(1 + monthlyInterest, numberOfPayments) - 1);
  '''
- Inputs needed for calculation:
  1. 'principal'
  2. 'monthlyInterest' (derived from 'annualInterest')
  3. 'numberOfPayments' (derived from 'years')

These values are currently calculated in different places, but conceptually, they are all part of the “Mortgage Calculation” process.

✅ Refactoring Plan: Bring them together into a single method, e.g.:

'''java
public static double calculateMortgage(
    int principal, 
    float annualInterest, 
    byte years
) { 
    // calculation logic here
}
'''

This method could later be reused in other programs.




4.5 Step 2 — Spotting Repetitive Patterns

Another common refactoring target is duplicate code — logic that repeats in multiple places.

Example in Our Program — The While Loops:
- Every input prompt (principal, interest rate, years) uses the same pattern:
  1. Start an infinite loop ('while (true)').
  2. Ask a question (prompt).
  3. Read the input.
  4. Validate it.
  5. If invalid → print error message and repeat.
  6. If valid → break out of the loop.

What changes between these loops?
- The question label (prompt text).
- The valid range (min/max values).
- The error message.

✅ Refactoring Plan: Create a generic method for reading an input within a range, such as:
'''java
public static int readNumber(String prompt, int min, int max) { 
    // loop + validation logic
}
'''
Then:
'''java
principal = readNumber("Principal ($1K - $1M): ", 1_000, 1_000_000);
annualInterest = readNumber("Annual Interest Rate: ", 1, 30);
years = readNumber("Period (Years): ", 1, 30);
'''




4.6 Visual Representation — Before & After Refactoring

Before (Monolithic main method):
'''
main()
 ├── Read principal  [loop + validation]
 ├── Read annual interest  [loop + validation]
 ├── Read years  [loop + validation]
 ├── Calculate mortgage (scattered logic)
 ├── Format result
 └── Print result
'''

After (Modular & Clean):
'''
main()
 ├── int principal       = readNumber(...);
 ├── float interestRate  = readNumber(...);
 ├── byte years          = readNumber(...);
 ├── double mortgage     = calculateMortgage(principal, interestRate, years);
 └── print(formatCurrency(mortgage));
'''




4.7 Refactoring Checklist

When cleaning code, always check:

1. Is there a logical grouping?
   - Related lines that should live in their own method.
2. Is there repetition?
   - Patterns repeated with small changes.
3. Is the method too long?
   - Consider splitting into smaller, focused methods.
4. Can logic be generalized?
   - Parameterize prompts, ranges, formulas.




4.8 Benefits of This Refactoring

- Improved Readability → 'main()' becomes high-level and self-explanatory.
- Better Maintainability → A change in one method won’t require changes in many places.
- Reusability → Mortgage calculation logic can be used in any project without rewriting.
- Reduced Bugs → Less code duplication → fewer points of failure.




4.9 Key Takeaways

- Refactoring is not about changing what the program does — only how the code is structured.
- Look for:
  1. Conceptually related logic scattered around → group it.
  2. Repetitive patterns → generalize into a reusable method.
- Keep methods short and focused for clarity and testability.
- After refactoring, code should read like a story.

5. Extracting Methods: 

5.1 Why We’re Doing This

Our 'main()' method in the Mortgage Calculator is currently too long and handles too many responsibilities:
- Reads inputs.
- Validates data.
- Performs mortgage calculations.
- Formats and prints the result.

This violates the Single Responsibility Principle (SRP) and makes the code:
- Harder to read.
- More difficult to reuse.
- Prone to duplication if we need similar functionality elsewhere.

Goal:  
Refactor the 'main()' method by extracting the mortgage calculation logic into a separate method.




5.2 What is Method Extraction?

Method extraction is a refactoring technique where we:
1. Identify a block of code that performs a clear, self-contained task.
2. Move it into a new method.
3. Replace the original block with a call to that method.

Benefits:
- Improves readability — 'main()' becomes high-level orchestration.
- Encourages reuse — the extracted method can be called from anywhere.
- Simplifies maintenance — changes to the calculation happen in one place.




5.3 Deciding on Method Parameters

When creating 'calculateMortgage()', we need:
1. Principal ('int')  
   → User’s loan amount.
2. Annual Interest Rate ('float')  
   → Easier to pass annual interest than monthly interest — monthly interest can be calculated internally.
3. Years ('byte')  
   → From years, we can derive the number of payments.

Method signature:
'''java
public static double calculateMortgage(
    int principal,
    float annualInterest,
    byte years
)
'''
- 'double' return type → Matches the required precision for mortgage payments.




5.4 Breaking Long Parameter Lines for Readability

Long parameter lists can hurt readability, so we can split them across lines:
'''java
public static double calculateMortgage(
    int principal,
    float annualInterest,
    byte years
) {
    // logic
}
'''




5.5 Moving the Calculation Logic

Original mortgage calculation in 'main()':
'''java
double mortgage = principal
        * (monthlyInterest * Math.pow(1 + monthlyInterest, numberOfPayments))
        / (Math.pow(1 + monthlyInterest, numberOfPayments) - 1);
'''

Steps to move it:
1. Cut calculation code from 'main()' ('Cmd + X' on Mac, 'Ctrl + X' on Windows).
2. Paste it into 'calculateMortgage()'.
3. Move all dependent variables ('monthlyInterest', 'numberOfPayments', constants) into the new method.




5.6 Bringing in Required Variables

Dependencies:
- Constants:
  '''java
  final byte MONTHS_IN_YEAR = 12;
  final byte PERCENT = 100;
  '''
- Monthly Interest:
  '''java
  float monthlyInterest = annualInterest / PERCENT / MONTHS_IN_YEAR;
  '''
- Number of Payments:
  '''java
  short numberOfPayments = (short) (years * MONTHS_IN_YEAR);
  '''

All of these now live inside 'calculateMortgage()'.




5.7 Why Use 'short' for Number of Payments?

- Reason: Even for the longest loan term (30 years),  
  \( 30 \times 12 = 360 \) payments — fits within 'short' range.
- Typecasting Required:  
  By default, multiplication of 'byte' values is promoted to 'int', so:
  '''java
  short numberOfPayments = (short) (years * MONTHS_IN_YEAR);
  '''
  Parentheses ensure the entire expression is cast to 'short'.




5.8 Returning the Result

Once the mortgage is calculated:
'''java
return mortgage;
'''
Now, 'main()' can store this value in a local variable.




5.9 Updating the Main Method

Before refactoring:
'''java
double mortgage = principal
        * (monthlyInterest * Math.pow(1 + monthlyInterest, numberOfPayments))
        / (Math.pow(1 + monthlyInterest, numberOfPayments) - 1);
'''

After refactoring:
'''java
double mortgage = calculateMortgage(principal, annualInterest, years);
'''




5.10 Handling Scope Issues

When calling 'calculateMortgage()' in 'main()', we initially got compilation errors for 'annualInterest' and 'years':
- Cause: They were declared inside while loops → only available in that block’s scope.
- Fix: Move their declaration to the top of 'main()':
  '''java
  int principal = 0;
  float annualInterest = 0;
  byte years = 0;
  '''
  Then assign their values inside the loops.




5.11 Final Refactored Code

'''java
package com.codewithmosh;

import java.text.NumberFormat;
import java.util.Scanner;

public class Main {

    public static void main(String[] args) {
        int principal = 0;
        float annualInterest = 0;
        byte years = 0;

        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("Principal: ");
            principal = scanner.nextInt();
            if (principal >= 1_000 && principal <= 1_000_000) break;
            System.out.println("Enter a value between 1,000 and 1,000,000");
        }

        while (true) {
            System.out.print("Annual Interest Rate: ");
            annualInterest = scanner.nextFloat();
            if (annualInterest >= 1 && annualInterest <= 30) break;
            System.out.println("Enter a value between 1 and 30");
        }

        while (true) {
            System.out.print("Period (Years): ");
            years = scanner.nextByte();
            if (years >= 1 && years <= 30) break;
            System.out.println("Enter a value between 1 and 30.");
        }

        double mortgage = calculateMortgage(principal, annualInterest, years);
        String mortgageFormatted = NumberFormat.getCurrencyInstance().format(mortgage);
        System.out.println("Mortgage: " + mortgageFormatted);
    }

    public static double calculateMortgage(
            int principal,
            float annualInterest,
            byte years
    ) {
        final byte MONTHS_IN_YEAR = 12;
        final byte PERCENT = 100;

        float monthlyInterest = annualInterest / PERCENT / MONTHS_IN_YEAR;
        short numberOfPayments = (short) (years * MONTHS_IN_YEAR);

        return principal
                * (monthlyInterest * Math.pow(1 + monthlyInterest, numberOfPayments))
                / (Math.pow(1 + monthlyInterest, numberOfPayments) - 1);
    }
}
'''




5.12 Visual — Before vs After Extraction

Before (inside 'main()'):
'''
main()
 ├── read inputs
 ├── validate inputs
 ├── calculate monthlyInterest
 ├── calculate numberOfPayments
 ├── calculate mortgage
 ├── format & print
'''

After Extraction:
'''
main()
 ├── read inputs
 ├── validate inputs
 ├── mortgage = calculateMortgage(principal, rate, years)
 ├── format & print

calculateMortgage()
 ├── constants
 ├── monthlyInterest
 ├── numberOfPayments
 ├── compute formula
 └── return mortgage
'''




5.13 Key Takeaways

- Method extraction centralizes logic, making it reusable and easier to maintain.
- Always pass only what is necessary as parameters.
- Keep calculations inside the method they belong to — reduces dependency on 'main()'.
- Be mindful of scope when moving code — variables in loops may need to be declared higher.
- Choose the most appropriate data type ('short' instead of 'float' for integer counts like payments).

6. Refactoring Repetitive Patterns — Comprehensive, Detailed Notes



6.1 Objective

Our Mortgage Calculator still has repeated patterns — specifically, three nearly identical 'while (true)' loops:
1. Asking for Principal.
2. Asking for Annual Interest Rate.
3. Asking for Period (Years).

These loops:
- Re-prompt until valid input is given.
- Differ only in prompt text, valid range, and target variable type.

Goal: Remove duplication by extracting a reusable, parameterized method.




6.2 Problem Analysis — Why Refactor These Loops?

# Before:
We have three loops like:
'''java

- Code duplication → Every future edit (like improved validation or formatting) must be repeated in multiple places.
- Harder to maintain → Any bug fix requires updating all three loops.

We want one generic method:
- Name: 'readNumber'
- Parameters:
  1. 'String prompt' → The question label.
  2. 'double min' → Minimum acceptable value.
  3. 'double max' → Maximum acceptable value.
- Return: 'double' →  
  - Flexible enough to be cast into 'int', 'float', or 'byte' as needed.
  - Avoids writing multiple versions ('readByte', 'readFloat', 'readInt').

7.4 Understanding the Payment Schedule Calculation

We need a formula to calculate the remaining loan balance after 'p' payments.


# Formula from MortgageProfessor.com
Given:
- L = Loan amount (principal)
- c = Monthly interest rate  
  → \( c = \frac{\text{Annual Interest Rate}}{100 \times 12} \)
- n = Total number of payments  
  → \( n = \text{Years} \times 12 \)
- p = Number of payments made

Formula:
\[
B = L \times \frac{(1 + c)^n - (1 + c)^p}{(1 + c)^n - 1}
\]

Where:
- \( B \) = Remaining balance after 'p' payments.
- \( L \times \ldots \) → Loan amount multiplied by a fraction:
  - Numerator:
    - \((1 + c)^n\) → Growth factor over the whole term.
    - Subtract \((1 + c)^p\) → Removes payments already made.
  - Denominator:
    - \((1 + c)^n - 1\) → Same as mortgage formula’s denominator.




7.5 Breaking Down the Formula

1. Monthly Interest Rate ('c')
   \[
   c = \frac{\text{Annual Interest Rate}}{100 \times 12}
   \]
   Example:  
   Annual Rate = 4% →  
   \( c = 0.04 / 12 = 0.003333... \)

2. Total Payments ('n')
   \[
   n = \text{Years} \times 12
   \]
   Example: 10 years → \( n = 10 \times 12 = 120 \) payments.

3. Payments Made ('p')
   Increment from '1' to 'n' in a loop.

4. Remaining Balance Calculation
   Plug L, c, n, and current p into:
   \[
   B = L \times \frac{(1 + c)^n - (1 + c)^p}{(1 + c)^n - 1}
   \]

     - Print the balance formatted as currency.

3. Keep the code clean and modular:
   - No complex logic inline — all calculations in methods.
   - No duplication — one balance formula method reused.

import java.util.Scanner;

public class Main {
    final static byte MONTHS_IN_YEAR = 12;
    final static byte PERCENT = 100;

    public static void main(String[] args) {
        int principal = (int) readNumber("Principal: ", 1000, 1_000_000);
        float annualInterest = (float) readNumber("Annual Interest Rate: ", 1, 30);
        byte years = (byte) readNumber("Period (Years): ", 1, 30);

        printMortgage(principal, annualInterest, years);
        printPaymentSchedule(principal, annualInterest, years);
    }

    private static void printMortgage(int principal, float annualInterest, byte years) {
        double mortgage = calculateMortgage(principal, annualInterest, years);
        String mortgageFormatted = NumberFormat.getCurrencyInstance().format(mortgage);
        System.out.println();
        System.out.println("MORTGAGE");
        System.out.println("--------");
        System.out.println("Monthly Payments: " + mortgageFormatted);
    }

    private static void printPaymentSchedule(int principal, float annualInterest, byte years) {
        System.out.println();
        System.out.println("PAYMENT SCHEDULE");
        System.out.println("----------------");
        for (short month = 1; month <= years * MONTHS_IN_YEAR; month++) {
            double balance = calculateBalance(principal, annualInterest, years, month);
            System.out.println(NumberFormat.getCurrencyInstance().format(balance));
        }
    }

    public static double readNumber(String prompt, double min, double max) {
        Scanner scanner = new Scanner(System.in);
        double value;
        while (true) {
            System.out.print(prompt);
            value = scanner.nextFloat();
            if (value >= min && value <= max)
                break;
            System.out.println("Enter a value between " + min + " and " + max);
        }
        return value;
    }

    public static double calculateBalance(
            int principal,
            float annualInterest,
            byte years,
            short numberOfPaymentsMade
    ) {
        float monthlyInterest = annualInterest / PERCENT / MONTHS_IN_YEAR;
        float numberOfPayments = years * MONTHS_IN_YEAR;

        double balance = principal
                * (Math.pow(1 + monthlyInterest, numberOfPayments)
                - Math.pow(1 + monthlyInterest, numberOfPaymentsMade))
                / (Math.pow(1 + monthlyInterest, numberOfPayments) - 1);

        return balance;
    }

    public static double calculateMortgage(
            int principal,
            float annualInterest,
            byte years) {

        float monthlyInterest = annualInterest / PERCENT / MONTHS_IN_YEAR;
        float numberOfPayments = years * MONTHS_IN_YEAR;

        double mortgage = principal
                * (monthlyInterest * Math.pow(1 + monthlyInterest, numberOfPayments))
                / (Math.pow(1 + monthlyInterest, numberOfPayments) - 1);

        return mortgage;
    }
}

10. Summary — Clean Coding & Refactoring Best Practices


10.1 Understanding Clean Coding & Refactoring

In this section, we learned the principles of clean coding and the art of refactoring.

Refactoring is:
The process of restructuring existing code without changing its external behavior.

Purpose:
- Improve readability.
- Enhance maintainability.
- Increase reusability.
- Reduce bugs by making code easier to understand and modify.

Key point: Refactoring never changes *what* the code does, only *how* the code is organized.




10.2 Why Refactoring Matters

As projects grow:
- Methods naturally get longer.
- Responsibilities become mixed.
- Patterns of repetition creep in.

Without refactoring:
- Code becomes harder to read.
- Maintenance costs rise.
- Risk of introducing bugs increases.




10.3 Best Practice — Method Length

- Ideal: 5–10 lines per method.
- Maximum: 20 lines.  
  If a method exceeds this:
  - It’s probably doing too much.
  - It violates the Single Responsibility Principle (SRP).
  - It’s a candidate for extraction into smaller methods.




10.4 How to Identify Refactoring Opportunities

When reviewing code, focus on:

# 1. Repetitive Patterns
- Code blocks that look almost identical except for small variations.
- Example: Multiple input-validation loops in the Mortgage Calculator.

✅ Action: Create a single parameterized method to replace all duplicates.


# 2. Highly Related Statements
- Lines that always occur together and serve one clear purpose.
- Example:  
  - Printing the Mortgage Summary.
  - Printing the Payment Schedule.

✅ Action: Group and extract them into clearly named, separate methods.




10.5 Refactoring Workflow

1. Locate candidates — repetition or high cohesion.
2. Extract method — give it a meaningful name that reflects its purpose.
3. Replace original code with the method call.
4. Test after each change to confirm behavior remains unchanged.




10.6 Benefits of Refactoring

- Readability: Code reads like a story; 'main()' becomes high-level orchestration.
- Maintainability: Easy to make changes without breaking unrelated areas.
- Reusability: Extracted logic can be used elsewhere without duplication.
- Debugging: Smaller methods make isolating problems easier.




10.7 Visual — When to Extract a Method

'''
Before:
main()
 ├── read inputs
 ├── validate inputs
 ├── calculate results
 ├── print summary
 └── print schedule
'''

'''
After:
main()
 ├── principal = readNumber(...)
 ├── rate      = readNumber(...)
 ├── years     = readNumber(...)
 ├── printMortgage(principal, rate, years)
 └── printPaymentSchedule(principal, rate, years)
'''




10.8 Golden Rules to Remember

- Do one thing per method.
- Name methods clearly — names should explain *what* the method does, not *how*.
- Avoid magic numbers — use constants.
- Keep 'main()' clean — it should coordinate, not implement.
- Refactor regularly — don't wait until the code becomes unmanageable.

2. Types of Errors: 

2.1 Introduction

When building Java applications, we inevitably encounter errors — situations where our code either:
- Fails to compile (caught before the program runs), or
- Fails during execution (caught while the program is running).

Understanding the types of errors, their causes, and how to approach fixing them is essential for every Java developer.




2.2 The Two Broad Categories of Errors

| Error Type            | When It Occurs       | Alternate Name          | Typical Cause                                           |
|-----------------------|----------------------|-------------------------|---------------------------------------------------------|
| Compile-time Errors   | During compilation   | Syntax Errors           | Breaking Java's grammar rules or type system            |
| Run-time Errors       | While program is running | Execution Errors    | Invalid operations, unexpected inputs, faulty logic     |


2.2.1 Compile-time Errors (Syntax Errors)

Definition:  
Errors detected by the Java compiler before your program runs, preventing it from producing a '.class' file.

Causes:
- Grammar violations — breaking Java’s syntax rules.
- Type mismatches — assigning incompatible types.
- Missing elements — e.g., semicolons, brackets.
- Invalid references — calling variables or methods that don’t exist.

Characteristics:
- Easy to find — compilers and IDEs (like IntelliJ IDEA) highlight these errors instantly.
- Prevent the program from compiling until fixed.
- Typically shown with red underlines and error messages.

Examples:
'''java
System.out.println("Hello World"  // Missing closing parenthesis and semicolon
int x = "text";  // Type mismatch: assigning String to int
'''

Fixing Strategy:
1. Read the compiler/IDE’s error message carefully — it usually points to where and why the error exists.
2. Correct the syntax or type issue.
3. If unclear:
   - Search the exact error message on Google or StackOverflow.
   - 99% of the time, someone else has faced the same issue, and solutions are readily available.




2.2.2 Run-time Errors

Definition:  
Errors that occur after the program successfully compiles, during execution.

Causes:
- Invalid operations at runtime (e.g., dividing by zero).
- Accessing null objects (NullPointerException).
- Invalid array indexing.
- File operations failing because the file does not exist.
- External factors (e.g., network issues, unavailable resources).

Characteristics:
- Program starts running successfully but crashes or behaves incorrectly at some point.
- Often produce exceptions (error objects) in Java, such as:
  - 'ArithmeticException'
  - 'ArrayIndexOutOfBoundsException'
  - 'NullPointerException'
- Can be harder to pinpoint without examining the program’s state at the time of the crash.

Example:
'''java
int x = 10 / 0; // ArithmeticException: / by zero
String s = null;
System.out.println(s.length()); // NullPointerException
'''




2.3 Why Compile-time Errors Are Easier to Fix

- They stop you immediately during compilation.
- Modern IDEs like IntelliJ offer real-time feedback with:
  - Red underlines
  - Tooltips explaining the error
  - Quick-fix suggestions (e.g., auto-importing missing classes)
- Often, the cause is obvious (missing bracket, wrong type, etc.).




2.4 Why Run-time Errors Are Trickier

- The program appears fine until a certain input or condition triggers the error.
- May depend on specific execution paths or data states.
- To track them down, you need to know what was happening in memory when the crash occurred.

Solution:  
Use a Debugger to:
- Run the code step-by-step.
- Inspect variable values at each step.
- See the exact line and condition that causes the failure.




2.5 Debugging as the Key to Fixing Run-time Errors

Debugging involves:
1. Setting breakpoints to pause execution at a certain line.
2. Stepping line-by-line to see the flow of logic.
3. Inspecting variable states to check if they hold expected values.
4. Identifying where and why something went wrong.

In IntelliJ IDEA:
- The debugger panel lets you:
  - Watch variables.
  - Evaluate expressions at runtime.
  - Navigate the call stack to trace the flow.




2.6 Visual Overview

Compile-time Error Cycle:
'''
Write Code → Compile → ❌ Syntax/Type Error → Fix → Compile Again → ✅
'''

Run-time Error Cycle:
'''
Write Code → Compile → Run → ❌ Crash/Unexpected Output → Debug → Fix → ✅
'''




2.7 Key Takeaways

- Compile-time errors:
  - Detected early.
  - Typically easier to fix.
  - Caused by breaking syntax or type rules.
- Run-time errors:
  - Appear only during execution.
  - Often require debugging tools to trace and fix.
- StackOverflow & Google:
  - Valuable resources for troubleshooting unexpected or unclear errors.
- Debugging is an essential skill — it turns “mysterious crashes” into “solvable puzzles”.

3. Common Syntax Errors: 


3.1 Introduction

In Java, compile-time errors (often called *syntax errors*) occur when the code you write violates Java’s syntax rules or grammar.  
The compiler detects these issues before the program is run, and they must be fixed before your code can execute.

In this section, we will explore the most common compile-time errors that beginners frequently encounter, why they happen, and how to prevent them.




3.2 Common Compile-Time Errors and Their Causes

# 1. Declaring a Variable Without a Type
Mistake:
'''java
name = "John"; // ❌ Missing data type
'''
Why it happens:
- In languages like Python or JavaScript, variables can be declared without explicitly stating the type.
- In Java, all variables must have a declared type.

Fix:
'''java
String name = "John"; // ✅ Correct — specifies the type
'''
Rule: Always declare a variable with its type ('int', 'String', 'double', etc.).


# 2. Missing Semicolon
Mistake:
'''java
System.out.println("Hello World") // ❌ Missing semicolon
'''
Why it happens:
- Every Java statement (except declarations of code blocks) must end with a semicolon ';'.
- Beginners often forget it after method calls or variable assignments.

Fix:
'''java
System.out.println("Hello World"); // ✅ Correct
'''
Note: You do not add semicolons after:
- Class declarations
- Method declarations
- Control structure headers ('if', 'while', 'for', etc.)


# 3. Calling a Method Without Parentheses
Mistake:
'''java
System.out.println; // ❌ Missing parentheses
'''
Why it happens:
- Beginners sometimes treat methods like variables.
- In Java, all methods require parentheses — even if they have no parameters.

Fix:
'''java
System.out.println(); // ✅ Correct — parentheses indicate a method call
'''


# 4. Forgetting String Quotes
Mistake:
'''java
System.out.println(Hello); // ❌ Missing quotes around string
'''
Why it happens:
- In Java, double quotes ('"') are required for strings.
- Single quotes (''') are for a single character, not strings.

Fix:
'''java
System.out.println("Hello"); // ✅ String literal
System.out.println('H');     // ✅ Character literal
'''


# 5. Misspelling or Incorrectly Capitalizing Variables
Mistake:
'''java
String name = "John";
System.out.println(Name); // ❌ Incorrect capitalization
'''
Why it happens:
- Java is case-sensitive:
  - 'Name' and 'name' are different identifiers.
- Misspellings or wrong capitalization lead to "cannot find symbol" errors.

Fix:
'''java
System.out.println(name); // ✅ Matches variable name exactly
'''


# 6. Using Reserved Keywords as Identifiers
Mistake:
'''java
int class = 5; // ❌ 'class' is reserved
'''
Why it happens:
- Java has reserved keywords (e.g., 'class', 'public', 'static', 'void', etc.).
- These cannot be used as:
  - Variable names
  - Method names
  - Class names

Fix:
'''java
int myClass = 5; // ✅ Choose a different identifier
'''
Tip: Your IDE will highlight reserved keywords automatically.


# 7. Using a Single Equals Sign ('=') in Comparisons
Mistake:
'''java
int x = 0;
if (x = 2) { // ❌ Assignment, not comparison
    System.out.println("Equal");
}
'''
Why it happens:
- In Java, '=' is assignment, not equality check.
- Comparisons use double equals '=='.

Fix:
'''java
if (x == 2) { // ✅ Correct equality check
    System.out.println("Equal");
}
'''
Rule: Always use '==' for primitive equality checks, and '.equals()' for object content comparison.




3.3 Quick Reference Table — Common Syntax Errors

| Mistake | Cause | Fix |
|---------|-------|-----|
| 'name = "John";' | Missing type | 'String name = "John";' |
| Missing ';' | Forgot to end statement | Add ';' at the end |
| 'System.out.println;' | No parentheses | 'System.out.println();' |
| 'System.out.println(Hello);' | Missing quotes | 'System.out.println("Hello");' |
| Wrong capitalization | Java is case-sensitive | Match exact name |
| 'int class = 1;' | Using reserved keyword | Rename variable |
| 'if (x = 2)' | Using assignment instead of comparison | Use '==' for primitives |




3.4 Visual Guide — Error Sources

'''
[Variable Declaration] → Missing Type / Reserved Keyword / Misspelling
[Statements]           → Missing Semicolon
[Method Calls]         → Missing Parentheses
[Strings]               → Missing or Wrong Quotes
[Comparisons]          → Using '=' instead of '=='
'''




3.5 Key Takeaways

- Java enforces strict syntax rules, so minor mistakes stop compilation.
- Case sensitivity means exact spelling matters.
- IDE assistance:
  - IntelliJ highlights issues in real-time.
  - Tooltips often explain exactly what to fix.
- For stubborn errors:
  - Read the error message carefully.
  - Search the exact message on StackOverflow or Google — most likely, it’s already been solved by others.

4. Debugging Java Applications: 



4. Debugging Java Applications — Detailed, Explorative Notes

4.1 Introduction

Debugging is the process of finding and removing errors (bugs) from a program.  
A bug is any defect that causes your program to behave unexpectedly — such as incorrect output, crashes, or skipped logic.

In this tutorial, we will:
- Learn how to debug Java programs using IntelliJ IDEA.
- Explore breakpoints, stepping commands, variable inspection, watches, and call stacks.
- Apply debugging to a real program with a deliberate bug.




4.2 The Example Program

'''java
public class Main {
    public static void main(String[] args) {
        System.out.println("Start");  
        printNumbers(4); 
        System.out.println("Finish"); 
    }
    
    public static void printNumbers(int limit){
        for(int i = 0; i < limit; i += 2)  // Bug: increments by 2
            System.out.println(i); 
    }
}
'''

Expected Output:
'''
Start
0
1
2
3
4
Finish
'''

Actual Output:
'''
Start
0
2
Finish
'''

Observation: Only even numbers are printed — meaning there’s a bug in the logic.




4.3 Setting a Breakpoint:

Purpose: A breakpoint tells the debugger to pause program execution at a specific line so you can inspect the program’s state.

How to set a breakpoint in IntelliJ:
1. Click in the left gray margin next to the desired code line (e.g., first line inside 'main()').
2. Alternatively, use the keyboard shortcut:  
   - Mac: ⌘ + F8  
   - Windows/Linux: Ctrl + F8
3. Clicking again on the red dot removes the breakpoint.




4.4 Running in Debug Mode

Instead of clicking Run, choose Debug:
- Menu: 'Run → Debug 'Main''
- Shortcut:  
  - Mac: Control + D  
  - Windows/Linux: Shift + F9

When the program starts, it pauses at the breakpoint before executing that line.




4.5 Debugger Interface Overview in IntelliJ

When in debug mode, a Debugger Panel appears:
- Toolbar: Contains stepping and control icons.
- Variables Window: Shows current variables in scope and their values.
- Watches Panel: Lets you manually track specific variables/expressions.
- Frames/Call Stack Window: Shows method call history in reverse order.




4.6 Stepping Through the Code

# 1. Step Over (F8)
Executes the current line without entering into method calls.  
Example: If on 'printNumbers(4)', it will execute the entire method and pause at the next line in 'main()'.

# 2. Step Into (F7)
Executes the current line and enters into the method being called so you can debug it line-by-line.

# 3. Step Out (Shift + F8)
Executes the remaining lines of the current method and returns to the caller.




4.7 Debugging the Bug

1. Start debugging from the beginning — program stops at the breakpoint in 'main()'.
2. Step Over 'System.out.println("Start")' — see '"Start"' in console.
3. Step Over 'printNumbers(4)' — outputs only '0' and '2'.  
   This confirms the bug is inside 'printNumbers()'.
4. Restart debug mode — this time Step Into 'printNumbers(4)'.




4.8 Inspecting Variables

Inside 'printNumbers()':
'''java
for (int i = 0; i < limit; i += 2)
'''
- The 'Variables' window shows:
  - 'limit = 4' (passed from 'main()').
- After the first loop iteration, 'i = 0'.
- Incrementing by 2 ('i += 2') skips odd numbers.




4.9 Adding Watches

If a variable is not in the Variables window:
- Click + in the Watches panel.
- Type the variable/expression name (e.g., 'i').
- Watches update live during execution.

You can remove unnecessary watches to avoid clutter.




4.10 Fixing the Bug

Change:
'''java
i += 2
'''
To:
'''java
i++
'''
Or:
'''java
i += 1
'''
Now the program will print all sequential numbers.




4.11 Restarting Debugging at Specific Points

You don’t have to restart from 'main()' every time:
- Remove the old breakpoint.
- Add a new one where the bug likely occurs (inside 'printNumbers()').
- Use the Resume Program button (▶) to jump directly to that point.




4.12 Skipping the Rest of a Method

When you’ve inspected enough inside a method and want to return to its caller:
- Use Step Out (Shift + F8).




4.13 Understanding the Call Stack (Frames Window)

The Frames Window shows the method call history:
- Last called method is at the top.
- Execution starts in 'main()' → calls 'printNumbers()'.
- Useful for:
  - Seeing how you got to this point.
  - Navigating back up the chain of calls in complex programs.




4.14 Final Corrected Code

'''java
public class Main {
    public static void main(String[] args) {
        System.out.println("Start");
        printNumbers(4);
        System.out.println("Finish");
    }

    public static void printNumbers(int limit) {
        for (int i = 0; i <= limit; i++)  // fixed increment and <=
            System.out.println(i);
    }
}
'''

Expected Output:
'''
Start
0
1
2
3
4
Finish
'''




4.15 Debugging Process Recap

1. Set Breakpoint where you suspect issues.
2. Run in Debug Mode.
3. Step Through Code with:
   - Step Over (F8)
   - Step Into (F7)
   - Step Out (Shift + F8)
4. Inspect Variables in the Variables Window.
5. Add Watches for critical expressions.
6. Use Call Stack to trace execution paths.
7. Fix the Bug and retest.




4.16 Key Takeaways

- Debugging helps you find the exact cause of a bug instead of guessing.
- Breakpoints save time in large programs by letting you jump directly to problem areas.
- IntelliJ’s Debugger provides:
  - Variable inspection
  - Watches
  - Call Stack navigation
- Debugging is an essential skill — especially when dealing with complex logic or hidden runtime issues.

5. Packaging Java Applications: 


5. Packaging Java Applications — Detailed and Comprehensive Notes



5.1 Introduction to Packaging Java Applications

After writing and testing a Java application, the final step before sharing it with others is deployment — making it possible for others to run your program on their machines.

In this context, packaging means taking all the necessary compiled code, resources, and dependencies and bundling them into a single, distributable file.

Scope of This Tutorial
- We focus on console/command-line applications (like those we built in this course).
- We’re not covering packaging web or mobile applications here, because they require additional, platform-specific steps.
- For Java desktop, web, and Android projects, deployment is more complex, often involving tools such as Maven, Gradle, application servers, or app stores.




5.2 Understanding JAR Files

- JAR = Java ARchive
- It's a compressed package format (similar to '.zip') for Java applications.
- Contains:
  - Compiled bytecode files ('.class')
  - Metadata (like 'MANIFEST.MF')
  - Optional resource files (images, text, configuration files)
  - Optional libraries (other '.jar' dependencies)

Purpose:
- Convenient distribution — only one file to share.
- Ensures all required compiled classes are bundled together.
- Can be executed directly if it contains a Main Class.




5.3 Runtime Requirements

For anyone to run your JAR file:
- They must have a Java Runtime Environment (JRE) installed.
- If they don’t:
  - They can download it from [https://java.com/download](https://java.com/download).
- On Windows, capitalization in file names isn’t enforced;  
  on macOS and Linux, capitalization matters ('HelloWorld.jar' ≠ 'helloworld.jar').




5.4 Example Program for Packaging

'''java
package com.codewithmosh;

public class Main {
    public static void main(String[] args) {
        System.out.println("Hello World");
    }
}
'''

This simple program prints '"Hello World"' to the terminal.




5.5 Creating a JAR File in IntelliJ IDEA

# Step 1 — Open Project Structure
1. Go to File → Project Structure.
2. In the left sidebar, select Artifacts.


# Step 2 — Add a New Artifact
- Click '+' to add a new artifact.
- From the dropdown:
  - Choose JAR → From modules with dependencies.


# Step 3 — Configure Module and Main Class
- In the popup:
  1. Select the module — here it's our 'HelloWorld' module.
  2. Click the Main Class selector (magnifying glass icon).
  3. Select your 'Main' class (the one containing 'public static void main').
     - If you have multiple classes with 'main()' methods, they will all appear in the list.
- Optional: Decide how to handle dependencies.
  - In our example, there are none to configure.


# Step 4 — Save the Artifact
- Click OK — now you’ll see a new artifact entry under Artifacts.
- Click OK again to close Project Structure.




5.6 Building the JAR

1. From the Build menu, choose Build Artifacts.
2. Select the artifact you just created (e.g., 'HelloWorld:jar').
3. Choose Build.

Other options in the menu:
- Rebuild — Cleans and builds from scratch (good if something is corrupted).
- Clean — Deletes build output without creating a new build.




5.7 Locating the Generated JAR

- IntelliJ places artifacts in the 'out/artifacts' folder inside your project directory:
  '''
  ProjectRoot/
      out/
          artifacts/
              HelloWorld_jar/
                  HelloWorld.jar
  '''




5.8 Running the JAR File from Terminal

# Step 1 — Open in Terminal
- Right-click on the JAR file in IntelliJ’s Project panel → Open in Terminal.

---

# Step 2 — Run Using 'java -jar'
In the terminal:
'''bash
java -jar HelloWorld.jar
'''

Explanation:
- 'java' → invokes the Java Virtual Machine.
- '-jar' → tells Java you’re running a packaged application.
- 'HelloWorld.jar' → the JAR file to execute.

Example Output:
'''
Hello World
'''




5.9 Visual Representation of the Packaging Workflow

'''
Source Code (.java) → Compilation (javac) → Bytecode (.class) 
→ Package into JAR (with Main-Class manifest) → Distribute JAR 
→ java -jar MyApp.jar → Program Output
'''




5.10 Best Practices for Packaging

- Always define a Main Class in the JAR’s 'MANIFEST.MF' file — this ensures it’s executable without extra parameters.
- Use descriptive artifact names for clarity ('MortgageCalculator.jar' instead of 'Main.jar').
- If your app depends on external libraries:
  - Consider a fat JAR / uber JAR that bundles dependencies into one file.
  - Or distribute the JAR along with a '/lib' directory containing required libraries.
- Test the JAR outside IntelliJ to ensure it runs in a clean environment.




5.11 Key Takeaways

- JAR packaging allows easy distribution and execution of Java console programs.
- The Java Runtime Environment is required to run JAR files.
- IntelliJ’s Artifacts feature simplifies JAR creation:
  - Choose From modules with dependencies.
  - Select the Main Class.
  - Build and run with 'java -jar'.
- Proper packaging means others can run your program without touching your source code.

2. Programming Paradigms: 

2.1 Introduction to Programming Paradigms

In computer science, a programming paradigm is a style or methodology of writing and structuring code.  
It defines:
- How problems are approached and modeled.
- How solutions are expressed in code.

Programming paradigms are not programming languages themselves.  
Instead:
- Languages implement one or more paradigms.
- We classify languages by the paradigms they support.




2.2 Examples of Programming Paradigms

Some well-known paradigms include:
1. Procedural Programming — Focuses on sequences of instructions (e.g., C, Pascal).
2. Functional Programming — Treats computation as evaluation of mathematical functions; avoids changing state (e.g., Haskell, parts of Java, JavaScript).
3. Object-Oriented Programming (OOP) — Models problems using objects that encapsulate data and behavior (e.g., Java, C#, Python).
4. Event-Driven Programming — Execution flow determined by user actions/events (e.g., Java Swing, JavaScript UI apps).
5. Logic Programming — Based on formal logic and rule evaluation (e.g., Prolog).
6. Aspect-Oriented Programming (AOP) — Separates cross-cutting concerns (e.g., logging, security).




2.3 Multi-Paradigm vs. Single-Paradigm Languages

- Single-paradigm languages: Support only one style.  
  Example → Smalltalk: Pure object-oriented.
- Multi-paradigm languages: Support multiple styles.  
  Examples:
  - Python
  - Ruby
  - Java (supports OOP + functional features like lambdas and streams)
  - JavaScript




2.4 The Two Most Popular Paradigms Today

Although many paradigms exist, the two most dominant in modern development are:
- Object-Oriented Programming (OOP)
- Functional Programming (FP)




2.5 Object-Oriented Programming — Key Idea

In OOP, everything revolves around objects:
- Object → a self-contained unit that bundles:
  - Data (also called *state*) → stored in fields/attributes.
  - Behavior → implemented as methods/functions that operate on that data.
- Principle: Bring data and its related operations together into a single, reusable entity.

Visual Representation:
'''
+--------------------+
|   BankAccount      |
+--------------------+
| balance: double    |   <-- State (data)
+--------------------+
| deposit(amount)    |   <-- Behavior (method)
| withdraw(amount)   |
+--------------------+
'''




2.6 Functional Programming — Key Idea

In FP:
- Data and behavior are treated as fundamentally different and kept separate.
- Functions:
  - Don’t mutate (change) state.
  - Take input and return new output without side effects (pure functions).
- Code focuses on data transformation using function composition.

Visual Representation:
'''
Data ---> f1() ---> result1 ---> f2() ---> result2 ---> ...
'''



2.7 Solving the Same Problem in Both Paradigms

Example problem: Calculating total salary after tax deduction.

OOP approach:
'''java
Employee e = new Employee("John", 50000);
e.calculateNetSalary();
'''
- The 'Employee' object knows how to calculate its own net salary.

FP approach:
'''java
calculateNetSalary(employeeData);
'''
- A pure function takes raw employee data and returns the computed net salary.

Result: Same solution, different code structure and thought process.



2.8 Which Paradigm is Better?

Answer: It depends — there’s no universal “best” paradigm.

- Some developers love one paradigm and use it for everything (not always ideal).
- Others dislike a paradigm because they misunderstood or misapplied it.
  - Example: Many who “hate” OOP never truly learned its principles.
- OOP can be complex — many books and courses fail to explain it effectively.




2.9 Real-World Suitability (General Guidelines)

- OOP:
  - Well-suited for graphical user interfaces (GUIs).
  - Common in game development.
  - Helpful when modeling complex real-world entities.
- FP:
  - Ideal for high-reliability systems.
  - Works well with data pipelines where data is passed and transformed.
- Event-Driven:
  - Great for UI programming where actions are triggered by events.

> Note: These are guidelines, not hard rules. Context matters.




2.10 Mixing Paradigms

In a single application, you might:
- Use event-driven programming for the UI layer.
- Use OOP for domain/business logic.
- Use FP for data processing modules.

Why?
- No paradigm is perfect for all scenarios.
- The best choice is context-driven and problem-focused.




2.11 Core Software Engineering Principle
> “There’s no one-size-fits-all in software engineering.”

- Best language? Depends on the problem, constraints, and budget.
- Best framework? Depends on team skill set, project requirements, performance needs.
- Dogmatically applying one paradigm to all problems can lead to poor solutions.




2.12 Problem-Solving Comes First

Many developers:
- Get too attached to a tool/language/paradigm.
- Forget that the main goal is solving problems.

True problem solving means:
1. Clearly define the problem.
2. Identify possible solutions.
3. Compare trade-offs considering:
   - Project context
   - Constraints (time, budget, resources)
4. Choose the most fit-for-purpose approach.




2.13 Key Takeaways

- Programming paradigms are styles of structuring solutions — not languages themselves.
- Most modern languages (Java, Python, JavaScript) are multi-paradigm.
- OOP = unify data & behavior in objects.  
  FP = keep data & behavior separate and use pure functions.
- Use the right paradigm for the right problem.
- Stay flexible — avoid falling in love with one solution and applying it blindly.
- Context and constraints matter more than personal preference.

3. Benefits Of Object-oriented Programming: 

3.1 Introduction

Object-Oriented Programming (OOP) is a programming paradigm based on the concept of objects — self-contained entities that combine data (state) and behavior (methods/functions that operate on the data).  
These objects interact with each other to accomplish tasks within an application, much like how components in a real-world system work together.




3.2 Real-World Analogy — The Car Example

Think of a car:
- It is composed of hundreds or thousands of smaller parts, each functioning as an object:
  - Engine
  - Transmission
  - Wheels
  - Brakes
  - Sensors
- Each of these parts:
  - Is reusable in other cars (e.g., a specific tire model used in multiple vehicles).
  - Is replaceable — if a part malfunctions, it can be removed and swapped with another.

How this applies to OOP:
- A software application is similar — it consists of collaborating objects.
- If an object in the program fails, we can:
  - Fix that object without touching unrelated parts.
  - Replace it with another object (like swapping a faulty component in a car).




3.3 Core Benefits of OOP

# 1. Reduced Complexity
- Large, complex applications can be broken down into smaller, more manageable objects.
- Each object focuses on one responsibility (Single Responsibility Principle).
- Easier to understand, design, and reason about smaller parts.

Visual Representation:
'''
[Whole App]
   ↓ Break into ↓
[User Interface]  [Business Logic]  [Database Layer]
   ↓ Further ↓
[UI Button] [Login Manager] [SQL Query Builder]
'''


# 2. Easier Maintenance
- If there’s a bug, you can focus only on the faulty object.
- No need to sift through the entire application.
- Encourages modularity:
  - Code changes in one object don’t impact other parts (if well-encapsulated).
- Enables plug-and-play replacement of components.


# 3. Code Reuse
- Once an object is designed, coded, and tested, it can be reused:
  - In different parts of the same application.
  - In other applications entirely.
- This is especially valuable when building utility classes or modular libraries.

Example:
- An ImageFilter object in an image editing app:
  - Can be reused in:
    - Desktop image editors
    - Mobile photo editing apps
    - Online web-based editors
- Eliminates duplication of effort.


# 4. Faster Development
- Reuse of tested objects → less time spent reinventing the wheel.
- Teams can work on different objects in parallel without interfering with each other’s code.
- Libraries and frameworks built with OOP provide pre-made components that accelerate development.




3.4 Addressing Misconceptions

- Some developers claim OOP’s benefits are purely theoretical because:
  - They’ve never successfully reused or replaced objects in practice.
- The likely reason:  
  - OOP was not applied correctly.
  - Poor design can make objects tightly coupled, defeating OOP’s flexibility.

> Lesson: If a tool doesn’t work for you, it doesn’t necessarily mean the tool is bad — you might just be using it incorrectly.




3.5 Comparison with Functional Programming

- Advocates of Functional Programming (FP) argue that FP also delivers:
  - Reduced complexity
  - Easier maintenance
  - Reusability
  - Faster development
- This is true — both paradigms offer benefits, but neither is a one-size-fits-all solution.




3.6 The Balanced Approach

- Learn both paradigms:
  - OOP for problems best modeled as interacting entities.
  - FP for problems centered on data transformation and immutability.
- Choose the paradigm based on the problem, context, and constraints.




3.7 Visual Summary — OOP Benefits

'''
┌─────────────────────────────────────┐
│   BENEFITS OF OBJECT-ORIENTED PROG  │
├─────────────────────────────────────┤
│ 1. Reduced Complexity               │
│ 2. Easier Maintenance               │
│ 3. Code Reuse                       │
│ 4. Faster Development               │
└─────────────────────────────────────┘
'''




3.8 Key Takeaways

- OOP = Objects (State + Behavior) working together.
- Breaks down large problems into manageable, modular parts.
- Enables component replacement without breaking the whole system.
- Encourages reuse, reducing development effort and speeding up delivery.
- Neither OOP nor FP is always the best choice — context determines the right tool.
